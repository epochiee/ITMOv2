## Context Pack для первого рабочего сценария

### Факты и правила

- Вход: кодовый diff как строка. В учебной паре используется TRAINING_PR.diff.
- API должен валидировать вход, иначе неверный JSON вызывает KeyError и 500.
- Ответ должен иметь явную схему и предсказуемый формат для документации и клиентов.
- Нужно ограничить максимальный размер diff, чтобы не переполнять контекст LLM и не создавать DoS-нагрузку.
- Ошибки LLM/сети должны маппиться в контролируемые HTTP-ответы.

### Формат входа и результата

- Вход JSON: { "diff": string }
- Результат JSON: { "comment": string }

### Ограничения и запрещённые действия

- На паре не используется реальный GitHub PR; роль входа выполняет TRAINING_PR.diff.
- Нельзя публиковать открытый небезопасный эндпойнт без решения по аутентификации.
- Нельзя отправлять чрезмерно большие diff без лимитов и договорённостей.

### Хороший пример

- Вход: { "diff": "diff --git a/app/api.py b/app/api.py\n..." }
- Ответ: { "comment": "Found issues: ..." }
### Плохой пример

- Вход без ключа diff: { }
- Вход с неподдерживаемым типом diff: { "diff": 123 }
### Что пока неизвестно

- Требования к безопасности (нужен ли auth), максимальный размер diff, SLA и таймауты.
- Целевая версия Python и ограничения по runtime.
- Нужны ли runtime-проверки протокола LLM (isinstance/issubclass).
- См. контекст в context/telegram_chat_result.json (объявления, дедлайны, формат занятий, как сдавать PR, разъяснения по заданиям).

## Как использовали AI

- Для чего: собрать AS IS-контекст и Context Pack для первого сценария, зафиксировать вход/выход, ограничения и неизвестные.
- Тип промпта: zero-shot для baseline (P1-01) и master prompt для структурированного результата (P1-02).
- Строка в [`prompts.md`](prompts.md): P1-01, P1-02, раздел Master Prompt v1 и Сравнение двух запусков.
- Что проверил студент и какие исправления поручил агенту: сопоставили выводы с TRAINING_PR.diff, добавили формат входа/выхода, ограничения по размеру diff, фиксацию неизвестных (auth, SLA, версия Python).
