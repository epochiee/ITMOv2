# Практика 7.2. Обработка GitHub Issues и недельный отчёт

Сценарии покрывают пункты 1–6 [условия практики](../README.md). Они настроены на [epochiee/eve-industry-planner](https://github.com/epochiee/eve-industry-planner).

## Классификация Issues

1. Импортируйте [issue-classifier.json](issue-classifier.json) и сохраните сценарий. В ноде «Модель A» выберите credential VseLLM из практики 7.1. Модель — `openai/gpt-5`. Классификатор принимает `title` и `body`, возвращает `type` и `confidence` через Structured Output Parser.
2. Импортируйте [issue-triage.json](issue-triage.json). В ноде «Вызвать классификатор» выберите импортированный Sub-workflow и проверьте сопоставление `title → {{ $json.title }}` и `body → {{ $json.body }}`. Оставьте включённым ожидание завершения Sub-workflow.
3. Укажите credential GitHub в GitHub Trigger и во всех четырёх узлах «Лейбл: …». Для регистрации вебхука нужен доступ на запись к вебхукам репозитория, для лейблов — Issues Write. Создайте отсутствующие лейблы из таблицы ниже в GitHub. Сохраните и опубликуйте основной workflow.
4. После восстановления VseLLM откройте четыре тестовых Issue. Для каждого проверьте лейбл в GitHub и сохраните скриншот **Executions** с выбранной веткой. Покажите запуск Sub-workflow и его ответ с `type` и `confidence`.

| Заголовок Issue | Пример описания | Ожидаемый лейбл |
|---|---|---|
| Сбор за работу учитывается дважды | При нулевых ценах материалов и сборе 100 ISK калькулятор показывает 200 ISK себестоимости. | `bug` |
| Уточнить запуск проекта в README | Добавить указание, из какой папки запускать `npm ci` и `npm run dev`. | `task` |
| Добавить экспорт расчёта в CSV | Нужна кнопка выгрузки материалов и итогов партии. | `feature-request` |
| Что-то не так | Иногда всё странно. | `needs-triage` |

Switch направляет результат в `unknown`, если тип неизвестен или `confidence < 0.8`. Эта ветка только добавляет `needs-triage`. При `confidence = 0.8` известный тип проходит в свою ветку.

## Отчёт через Gmail

1. Импортируйте [weekly-report.json](weekly-report.json). Выберите credential GitHub в четырёх узлах поиска и Gmail OAuth2 в узле «Отправить HTML через Gmail». Запишите свой почтовый адрес вместо `set-recipient@example.invalid` в узле «Репозиторий, получатель и неделя».
2. Запустите сценарий вручную через **Execute workflow**. Он берёт предыдущую завершённую неделю по Москве. Если этой неделе не соответствует ни один тестовый Issue, можно дождаться её завершения или указать в `demoWeekStart` понедельник уже завершённой недели с тестовыми данными. Формат даты — `YYYY-MM-DD`. Проверьте, что тестовые Issues входят в выбранный период.
3. В **Executions** зафиксируйте четыре поисковых запроса и результат группировки. Сценарий запрашивает все созданные Issues и отдельно выборки по `bug`, `task`, `feature-request`. В отчёте есть итог, разбивка по типам и разбивка по авторам.
4. Сохраните скриншот входящего письма с таблицами. Для запуска по расписанию опубликуйте workflow. Cron `0 9 * * MON` срабатывает по понедельникам в 09:00 по Москве.

Для сдачи экспортируйте три настроенных сценария, приложите [ссылку на Issues](https://github.com/epochiee/eve-industry-planner/issues), скриншоты Executions и полученного письма.

## Сверхзадание. Повторная попытка после ревью

Обновлённый [ai-fix.json](ai-fix.json) при отклонении первой правки передаёт в `openai/gpt-5` исходный код, отклонённый diff и замечания `qwen/qwen3.7-max`. Модель может предложить одну новую версию той же ограниченной правки арифметики. Если версия проходит проверку, n8n добавляет новый коммит в ветку открытого PR и публикует отдельное ревью для этого коммита.

При успешном ревью GitHub Actions и слияние используют SHA одобренной версии. Если второе ревью отклонило правку, модель повторила первый вариант или не предложила допустимую правку, PR остаётся на ручную доработку. Повторная попытка выполняется один раз за запуск.

При импорте обновлённого сценария выберите свои GitHub и VseLLM credentials в добавленных нодах. Для проверки в **Executions** нужны первое отклонённое ревью, коммит доработки и второе ревью. В GitHub сравните SHA второго ревью и запуска `AI fix validation`.

Три базовых экспорта можно пересобрать из корня учебного репозитория:

```powershell
node practices/practice_07.1/n8n/generate.mjs --support
```
