# Практика 7.1. Ассистент для ревью «Верфи»

Импортируйте [pr-review.json](pr-review.json) в проект n8n. Сценарий настроен на [epochiee/eve-industry-planner](https://github.com/epochiee/eve-industry-planner). Для повторной генерации JSON из корня учебного репозитория выполните:

```powershell
node practices/practice_07.1/n8n/generate.mjs --review
node --test practices/practice_07.1/n8n/review.test.mjs
```

## Подключение

1. Для GitHub Trigger и трёх HTTP-узлов выберите GitHub credential с доступом именно к целевому репозиторию. Для регистрации вебхука нужен доступ на запись к вебхукам, для чтения diff и публикации ревью — к pull requests. Используйте HTTPS-адрес n8n, доступный с GitHub.
2. Для обеих нод OpenAI Chat Model выберите один credential VseLLM. В Base URL укажите `https://litellm.data-light.ru`. Укажите выданный для курса API key в credential n8n.
3. В том же проекте n8n создайте Data Table `pr_reviews`. Добавьте четыре колонки типа String.

   | Колонка | Значение |
   |---|---|
   | `pr_key` | ID репозитория и номер PR через двоеточие |
   | `pr_id` | Глобальный ID PR из GitHub |
   | `model` | ID модели последнего опубликованного ревью |
   | `reviewed_at` | Время записи в формате ISO 8601 |

4. Выберите эту таблицу в узлах «ID PR отсутствует в таблице» и «Записать ID проверенного PR». Обновите сопоставление колонок после выбора таблицы, если редактор n8n его сбросил. Опубликуйте workflow.

## Проверка на тестовом PR

| Действие | Ожидаемый результат | Что приложить |
|---|---|---|
| Открыть PR с небольшим текстовым diff и двумя отдельными блоками изменений | `openai/gpt-5` публикует ревью. В Data Table появляется строка с ID PR | Execution открытия, ссылка на PR, снимок Data Table |
| Оставить в PR комментарий `/make_ai_review` от участника репозитория после завершения первого execution | Выполнение останавливается на проверке таблицы. Ноды модели и публикации остаются невыполненными | Execution повторной команды |
| Оставить в том же PR комментарий `/make_other_ai_review` | `qwen/qwen3.7-max` публикует отдельное ревью с названием модели. Строка в таблице обновляется | Execution второй модели и ссылка на её ревью |
| Открыть Files changed | Под каждым доступным текстовым блоком есть комментарий ревью. Добавленные строки привязаны справа, блоки только с удалениями — слева | Ссылка на PR и снимок Files changed |

Если нужна отдельная проверка успешного запуска `/make_ai_review` на PR без ревью, откройте второй тестовый PR до публикации workflow. После публикации оставьте команду в этом PR.

Обе модели получают одинаковый промпт. На защите сравните конкретные замечания по одному блоку PR. Таблица проверяется до вызова основной модели и обновляется после успешного ответа GitHub. Проверка и запись выполняются разными нодами, поэтому при одновременной доставке событий возможны параллельные ревью ещё не обработанного PR. Для демонстрации дождитесь завершения каждого запуска.

Сценарий делит GitHub patch по заголовкам `@@`, проверяет длину блока и публикует комментарии как одно ревью, привязанное к SHA коммита. В сводке перечисляются файлы без текстового patch. Для демонстрации используйте до 40 блоков и короткий diff.
