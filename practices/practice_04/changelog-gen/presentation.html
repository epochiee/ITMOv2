changelog-gen: среда агента, skill и собственный MCP

Утилита читает git-историю в формате Conventional Commits и печатает changelog. Вокруг неё настроена среда для агента: правила, skill, MCP-сервер и hook.

Среда агента

Правила

AGENTS.md, CLAUDE.md (@AGENTS.md): структура, команды, правила коммитов и тестов, критерий «готово».

Skill

release-notes: template.md, validate.py.

MCP-сервер

server.py, .mcp.json: tool parse_commit поверх parser.py.

Hook

settings.json → check.sh: ruff + pytest после каждого Edit|Write; при сбое код 2 и вывод возвращаются агенту.

Единая точка проверки — bash scripts/check.sh: её запускает hook, она же критерий «готово» в AGENTS.md.

Собственный MCP: tool parse_commit

parse_commit("feat(api)!: drop v1")
  → {"ok": true, "type": "feat", "scope": "api", "description": "drop v1", "breaking": true}

parse_commit("update stuff")
  → {"ok": false, "error": "not a Conventional Commit header: 'update stuff'"}
  • Код: server.py; подключение: .mcp.json. Tool оборачивает changelog_gen.parser, поэтому разбор один и для кода, и для skill.
  • Сырые ответы агента, включая два ok: false (update stuff, wip stuff): run-mcp.txt.
  • Тесты: test_mcp_server.py (успех, ошибочный ввод, пустая строка).
  • Ошибка возвращается данными (is_error=False): клиент, смотрящий только на флаг, неверный ввод не заметит. Это осознанный выбор.

Skill release-notes: устройство

  1. Диапазон: от последнего тега, иначе от коммита, последним менявшего CHANGELOG.md, иначе весь HEAD.
  2. git log --format=%s <range>.
  3. MCP parse_commit на каждую тему; ok: false запоминается.
  4. Группировка: Breaking, Features, Fixes, Other; нераспознанное → Not recognized. Оформление по template.md.
  5. validate.py на новой секции: заголовок версии, непустые разделы, нет дублей.
  6. Запись сверху CHANGELOG.md и check.sh.

Файл: SKILL.md. Валидатор проверяет только структуру, а не соответствие истории.

Skill: запуск и результат

  • Первый прогон (история проекта): тегов нет → весь HEAD, 6 коммитов, 5 распознано, 1 нет (merge-коммит). Валидатор OK. Результат — секция 0.1.0 в CHANGELOG.md.
  • Найденный дефект: без тегов skill брал весь HEAD, и секция 0.2.0 задвоила записи 0.1.0. Диапазон исправлен в SKILL.md, секция сокращена; валидатор проверяют только на новой секции.
  • Песочница (тег v0.2.0, фича --title): диапазон v0.2.0..HEAD, 5 коммитов, wip stuff попал в Not recognized, валидатор: OK (код 0) и отказ на файле с пустой секцией (код 1). Лог: run-skill.txt.
  • Раздел Not recognized появился после первого прогона, когда нераспознанный merge-коммит терялся.

Трудности и вмешательства

  • Системный pip относился к Python 3.9 → .venv на 3.12.
  • В mcp 2.x FastMCP переименован в MCPServer; примеры в интернете устарели.
  • CRLF на Windows мог сломать check.sh → .gitattributes (LF для *.sh, *.py, *.md).
  • Проектный MCP потребовал перезапуска сессии и одобрения.
  • Агент испортил parser.py правкой скриптом через heredoc → git checkout, правка штатным Edit и правило в AGENTS.md.
  • Мой первый прогон check.sh не видел новых файлов → старые замечания ruff всплыли в hook.
  • По итогам ревизии: добавлен тест MCP-сервера, обновлён CHANGELOG.md, исправлен диапазон в skill.

Ограничения

  • Hook не видит правки через Bash; matcher не расширен (слишком шумно), вместо этого правило в AGENTS.md.
  • Числовой код возврата hook в сессии не виден; код 2 подтверждён только прямым запуском.
  • Фича --title и 25 тестов есть только в песочнице; в проекте 22 теста.
  • Загрузка skill как отдельного вызова в логах не видна; цитата правил AGENTS.md отдельным файлом не сохранена.
  • Видео снято раньше песочницы и текстовыми логами не подтверждается.
  • Валидатор проверяет структуру, а не соответствие истории.

Подробности: reflection.md.

Выводы

  • Чёткий критерий «готово» в AGENTS.md дал агенту точку остановки.
  • Hook ловит реальные сбои в момент правки, но видит только состояние на этот момент.
  • MCP-tool вместо regex: один источник правды для разбора коммитов.
  • Skill с валидатором даёт проверяемый результат, но качество зависит от шаблона и правила диапазона.
  • Worktree изолирует код, но не окружение: .venv и hook настраиваются отдельно.
