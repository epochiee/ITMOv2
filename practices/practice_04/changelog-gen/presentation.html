changelog-gen: настройка среды агента и две фичи

Утилита читает git-историю в формате Conventional Commits и печатает changelog. Сверху — среда для агента: правила, skill, MCP-сервер, hook.

Навигация: стрелки, пробел, Home/End. Ссылки ведут на файлы проекта (открывать из папки проекта).

Среда агента

Правила

AGENTS.md, CLAUDE.md (@AGENTS.md): команды, правила коммитов и тестов, критерий «готово».

Skill

release-notes: template.md, validate.py.

MCP-сервер

server.py, .mcp.json: tool parse_commit поверх parser.py.

Hook

settings.json → check.sh: ruff + pytest после каждого Edit|Write, при сбое код 2 и вывод агенту.

Фича A: группировка по типам

Ветка feature-a, коммит 2d5a0e5. Код: renderer.py, тесты: test_renderer.py.

## 1.0.0

### Features

- **api**: add x

### Fixes

- bug

### Other

- readme
  • Секции: Features (feat), Fixes (fix), Other (всё остальное).
  • Пустые секции не выводятся, порядок внутри секции сохраняется.

Фича B: breaking changes

Worktree ../changelog-gen-b, ветка feature-b, коммит 5cd5e05.

  • parser.py: breaking ставится по ! и по футеру BREAKING CHANGE: / BREAKING-CHANGE:.
  • cli.py: читает полные сообщения (%B%x00), иначе футер не виден.
  • renderer.py: отдельная секция Breaking Changes.
  • Тесты: test_parser.py, test_cli.py, test_renderer.py.

Worktree не содержит .venv: подключён junction mklink /J .venv ..\changelog-gen\.venv.

Слияние A и B

Коммит 42e3ff3. Конфликты в renderer.py и tests/test_renderer.py.

*   42e3ff3 Merge branch 'feature-b' into feature-a
|\
| * 5cd5e05 feat(parser): detect breaking changes ...
* | 2d5a0e5 feat(renderer): group changelog entries ...
* | 4c40e89 style: fix ruff findings ...
|/
* 53790a5 build: force LF line endings for shell scripts
  • Порядок: Breaking Changes, Features, Fixes, Other.
  • Breaking-коммит не дублируется в секции своего типа.
  • Итог: 19 тестов, bash scripts/check.sh → код 0.

Доказательство 2: MCP и skill

parse_commit("feat(api)!: drop v1")
  → {"ok": true, "type": "feat", "scope": "api", "description": "drop v1", "breaking": true}

parse_commit("update stuff")
  → {"ok": false, "error": "not a Conventional Commit header: 'update stuff'"}
  • Skill release-notes на истории проекта: тегов нет → весь HEAD, 6 коммитов.
  • Распознано 5, не распознан 1 (merge-коммит). Валидатор: OK, код 0.
  • Результат: CHANGELOG.md; нераспознанный коммит теперь попадает в секцию Not recognized.
  • Логи: mcp-calls.txt (клиент mcp_client.py, успех и ошибка), skill-run.txt, breaking-demo.txt (секция Breaking Changes на репозитории с ! и футером).

Трудности

  • Системный pip относился к Python 3.9 → .venv на 3.12.
  • В mcp 2.x FastMCP переименован в MCPServer; примеры в интернете устарели.
  • CRLF на Windows мог сломать check.sh → .gitattributes.
  • Проектный MCP потребовал перезапуска сессии и одобрения.
  • Ошибка агента: правка parser.py скриптом через heredoc испортила файл (CRLF, экранирование) → git checkout и правка штатным Edit.

Ограничения

  • Hook в worktree подтверждён живой сессией в changelog-gen-b: запись сломанного файла заблокирована (6 замечаний, из них 2 от нового файла), после исправления остались только 4 старых. Числового кода возврата агент не видит (он есть только в прямом запуске).
  • Подтверждение живой сессии — скриншот хода сессии (правило применено, три вызова MCP, блокировка записи hook, исправление) и сводная таблица агента. Сырые ответы MCP: used_4_tools.png. Запись и исправление файла в worktree: created_and_updated_py.png. Полного текста вывода ruff от hook в живой сессии на скриншотах нет (только пересказ агента); сырой вывод — в прямом запуске.
  • Перечитывание AGENTS.md: файл уже был в контексте, отдельных перечитываний нет.
  • Подтверждения — логи команд в evidence/, не скриншоты прошлых сессий.
  • MCP-tool возвращает ошибку данными (ok: false, is_error=False).

Подробности: reflection.md.

Выводы

  • Чёткий критерий «готово» в AGENTS.md дал агенту точку остановки.
  • Hook ловит реальные сбои, о которых агент иначе мог не узнать.
  • MCP-tool вместо regex: один источник правды для разбора коммитов.
  • Skill с валидатором даёт проверяемый результат, но качество зависит от шаблона.
  • Worktree изолирует код, но не окружение: .venv и hook настраиваются отдельно.
