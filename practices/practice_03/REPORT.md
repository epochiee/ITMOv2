# Отчёт: локальный помощник по проекту (Ollama + OpenCode)

## Железо и окружение

- **Хост**: Windows 11 Home Single Language, AMD Ryzen 5 5600H (6 cores / 12 threads),
  интегрированная графика Radeon (без дискретной GPU, без CUDA/ROCm). RAM 16 ГБ.
  Свободно на диске C: ~93 ГБ.
- **WSL2**: Ubuntu 26.04 LTS, видит все 12 vCPU, лимит RAM для VM — 7.5 ГиБ (`free -h`).
  Инференс идёт **только на CPU** (`ollama ps` → `PROCESSOR 100% CPU`); интегрированная
  графика не поддерживается Ollama на этом железе, offload на GPU не настраивался.
- **Версии**: Ollama 0.40.0, OpenCode 1.18.35, Python 3.14.4 (WSL).

## Модель

- **Разработчик / семейство / тег**: Qwen, Qwen3.5, `qwen3.5:4b` (base image ID `d8b0f5e9760c`).
- **Кастомный профиль**: `itmo-agent-4b` (ID `dcee7bd0dd63`), собран через
  `ollama create itmo-agent-4b -f Modelfile`.
- **Формат / квантизация / лицензия**: GGUF, Q4_K_M, Apache License 2.0, источник —
  встроенная библиотека моделей Ollama (`ollama pull qwen3.5:4b`).
- **Параметры**: 4.2B, architecture `qwen35`, capabilities: completion, vision, tools,
  thinking (нативный максимум контекста модели — 262144, в профиле ограничен до 8192).
- **Контекст и размещение**: `num_ctx=8192` (задан в `Modelfile`, подтверждён
  `ollama ps` → `CONTEXT 8192`). Полностью на CPU.

### Почему эта конфигурация

16 ГБ RAM хоста соответствуют уровню "4B-модель, контекст ~4–8K" — больше не позволяет
комфортно разместить веса + рантайм OpenCode/WSL. Контекст поднят с 4096 до 8192, так
как агентные ответы с вызовами инструментов (`glob`/`read`) быстро съедают короткое окно.
`qwen3.5:9b` не тестировалась: ~6.6 ГБ весов рискует не оставить памяти для OpenCode при
доступных ~7.5 ГиБ в WSL VM. Отдельно собран `itmo-agent` (`Modelfile.agent`, ctx 65536)
для проверки ресурсоёмкости большого контекста — для диалогового use-case он не
практичнее основной конфигурации (первая генерация после смены контекста требует
повторной полной загрузки весов), поэтому не используется для тестовых вопросов.

## Настройка

- `lab/Modelfile` — `FROM qwen3.5:4b`, `num_ctx 8192`, `temperature 0.2`, SYSTEM-промпт
  с требованиями: отвечать только по контексту, указывать `file:line`, явно сообщать
  об отсутствии данных, явно отмечать ложные предпосылки в вопросе.
- `lab/opencode.json` — провайдер `ollama` (`@ai-sdk/openai-compatible`,
  `baseURL: http://localhost:11434/v1`), модель `itmo-agent-4b` с
  `options.reasoningEffort: "none"`, агент `local-guide` с правами только на
  `read`/`glob`/`grep` (всё остальное — `deny`).
- Ollama запущен как systemd-сервис с явным `Environment=OLLAMA_NO_CLOUD=1`
  (override в `/etc/systemd/system/ollama.service.d/override.conf`), подтверждено
  логом `journalctl -u ollama` (`Ollama cloud disabled: true`) — исключает уход в
  облачный API модели даже случайно.
- `curl http://localhost:11434/api/version` отвечает и из WSL, и из Windows (WSL2
  localhost forwarding работает без правок `.wslconfig`).
- `ollama list` показывает только локально скачанные веса (`qwen3.5:0.8b/2b/4b`,
  `itmo-agent`, `itmo-agent-4b`) — других провайдеров модель не использует.

## Находка: `think` vs `reasoningEffort`

Endpoint `/v1/chat/completions` (его использует OpenCode через `@ai-sdk/openai-compatible`)
**игнорирует** Ollama-специфичный булев параметр `think`, хотя нативный `/api/chat` его
уважает. Рабочий способ отключить "размышления" через OpenAI-совместимый API — поле
`reasoning_effort: "none"` (см. `docs.ollama.com/openai`, раздел "Reasoning/thinking
control"). Без этого параметра один ответ в OpenCode занимал 250–900+ секунд, с ним —
единицы/десятки секунд. Это задано в `lab/opencode.json` как
`provider.ollama.models.itmo-agent-4b.options.reasoningEffort: "none"` и является
обязательным условием для использования этой модели в интерактивном режиме на доступном CPU.

## Пять вопросов — ответы `itmo-agent-4b` через OpenCode (`local-guide`)

Каждый вопрос запущен `opencode run` в новой сессии (без `--continue`), агент имеет
доступ только к `read`/`glob`/`grep`. Эталоны подготовлены заранее в
[`lab/ANSWER_KEY.md`](lab/ANSWER_KEY.md) путём прямого чтения `demo/service.py` и
`demo/test_service.py`; этот файл физически недоступен тестируемому агенту (лежит вне
`demo/`) и **не передавался** тестовой сессии.

## Скорость

Измерено через `/api/chat` напрямую (минуя OpenCode, чтобы исключить накладные расходы
HTTP-инструментов), `model=itmo-agent-4b`, `think=false`.

- **Холодный старт** (после `ollama stop itmo-agent-4b`): `wall=19.83s`,
  `load_duration=13.98s` — основное время уходит на загрузку весов (3.3 ГБ) с диска в RAM,
  не на генерацию.
- **Прогретые повторы** (модель остаётся в памяти): 7.59 / 7.96 / 8.03 токенов/с на
  вывод (decode). Медиана = 7.96 ток/с.
- **Метод замера**: `eval_count / (eval_duration / 1e9)` из нативного ответа `/api/chat`
  (decode-токены в секунду); `wall_seconds` — через `time.perf_counter()` вокруг
  HTTP-запроса (см. `lab/experiment.py`).
- **TTFT**: не измерялся — используется нестриминговый `stream:false`.

## Выводы

**Обнаруженное ограничение**: модель `itmo-agent-4b` (Qwen3.5 4B, Q4_K_M, ctx 8192,
temperature 0.2, строгий анти-галлюцинационный SYSTEM-промпт) **систематически
галлюцинирует**, когда вызовы инструментов (`read`/`glob`) завершаются ошибкой или дают
нулевой результат: вместо честного «нет данных» модель в 2 случаях из 5 (№2, №5) либо
выдумала несуществующую сигнатуру функции, либо утвердила факт, прямо противоположный
коду — даже явно признав в тексте ответа, что не видела контекста. Модель также не
всегда следует собственной инструкции про резервный `glob "**/*"` при неудаче первого
поиска (вопрос №1).

**Как проверяли**: все пять ответов сверены построчно с `lab/ANSWER_KEY.md`, эталоны
подготовлены до прогона тестовой сессии по прямому чтению кода. `make test` зелёный
(3/3 passed) — сам демо-код корректен, расхождения в ответах модели целиком на стороне
её интерпретации кода, а не бага в `demo/`.

**Итоговая конфигурация**: `itmo-agent-4b` (Qwen3.5 4B, Q4_K_M, ctx 8192, temperature 0.2)
с **обязательным** `options.reasoningEffort: "none"` в `opencode.json` — без этого
параметра конфигурация непригодна для интерактивной работы на доступном CPU
(4–15-минутные ответы). С этим параметром модель отвечает за единицы–десятки секунд, но
требует дополнительной проверки человеком (fact-checking) или более строгого
agentic-луппинга (принудительный повтор `glob`/`read` при первой неудаче) — на 4B-модели
такого размера и квантизации доверять автономным фактическим ответам без верификации
нельзя.

**Если работали в паре**: нет, работа выполнена на одном устройстве (AMD Ryzen 5 5600H,
16 ГБ RAM, см. "Железо и окружение").
