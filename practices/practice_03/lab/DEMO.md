# Инструкция: живое демо локальной модели через WSL

Цель — за время ревью показать, что локальный стек (WSL2 + Ollama + OpenCode) реально
работает полностью офлайн, без обращения к облачным API.

Все команды ниже выполняются **внутри WSL** (Ubuntu), если не сказано иное.
Рабочая директория: `practices/practice_03/lab` (доступна из WSL как
`/mnt/c/Users/<user>/.../ITMOv2/practices/practice_03/lab`).

## 0. За 5 минут до демо (прогрев, чтобы не ждать на ревью)

Холодный старт модели занимает ~1.5–2 минуты (загрузка весов 3.4 ГБ с диска в RAM),
а Ollama по умолчанию выгружает модель из памяти через ~5 минут простоя (`keep_alive`).
Поэтому прогрейте модель прямо перед показом ревьюверу:

```bash
wsl
cd /mnt/c/Users/<user>/Documents/ITMO/ITMOv2/practices/practice_03/lab

# сервис должен быть активен (поднимается автоматически при старте WSL,
# либо вручную при необходимости)
systemctl is-active ollama || sudo systemctl start ollama

# прогрев весов в RAM без реального вопроса
ollama run itmo-agent-4b "ping" --keepalive 30m
```

Проверьте, что модель осталась резидентной и видна интеграция с CPU:

```bash
ollama ps
# NAME                    ID         SIZE     PROCESSOR   CONTEXT   RUNNER     UNTIL
# itmo-agent-4b:latest    ...        3.4 GB   100% CPU    8192      llamacpp   29 minutes from now
```

`PROCESSOR 100% CPU` — подтверждение, что инференс идёт на CPU (ожидаемо: нет
дискретной GPU/CUDA/ROCm на этом железе).

## 1. Подтверждение офлайн-режима (показать ревьюверу перед запросом)

```bash
# локальный endpoint отвечает
curl -s http://localhost:11434/api/version
# {"version":"0.40.0"}

# облачный режим Ollama отключён явным override
systemctl show ollama -p Environment | tr ' ' '\n' | grep OLLAMA_NO_CLOUD
# OLLAMA_NO_CLOUD=1

# список моделей — все веса локальные
ollama list
```

Опционально — показать, что сети для внешних API нет/не используется: отключить
Wi-Fi/Ethernet на хосте перед запросом и показать, что ответ всё равно приходит
(если сеть реально недоступна на машине — самый наглядный аргумент).

## 2. Запуск тестового агента с рандомным промптом

`opencode` добавлен в `$PATH` через `~/.profile` (блок `if [ -d "$HOME/.opencode/bin" ]`),
поэтому доступен по короткому имени в любой login-сессии WSL (обычный `wsl` /
`bash -l`). Если команда не найдена — см. раздел 5 (Troubleshooting).

```bash
cd /mnt/c/Users/<user>/Documents/ITMO/ITMOv2/practices/practice_03/lab

# любой новый вопрос по demo/, которого нет в QUESTIONS.md/ANSWER_KEY.md —
# чтобы ревьювер видел, что ответ не заучен, а модель реально читает код
opencode run --agent local-guide \
  "Сколько раз можно подписать одно и то же имя? Проверь кодом и тестом."
```

Что должно произойти на экране (и что проговорить ревьюверу):
- в заголовке строки статуса видно `local-guide · itmo-agent-4b` — подтверждение,
  что используется локальная кастомная модель, а не облачный провайдер;
- видны вызовы инструментов (`Glob`/`Read`) — агент реально ходит в файлы `demo/`,
  а не угадывает по памяти;
- права агента ограничены (`opencode.json` → `permission: read/glob/grep: allow,
  * : deny`) — можно показать, что `write`/`bash`/`edit` недоступны, если
  специально попросить агента что-то изменить, он откажет или получит отказ в
  правах.

Ожидаемое время ответа при прогретой модели — единицы/десятки секунд
(при условии `reasoningEffort: "none"` в `opencode.json`, см. ниже). Если модель
успела выгрузиться (пауза >5 минут между демо-шагами) — первый ответ снова
займёт ~1.5–2 минуты, это нормально, стоит предупредить ревьювера заранее.

## 3. Показать конфигурацию (если спросят "как это настроено")

```bash
cat Modelfile          # num_ctx 8192, temperature 0.2, анти-галлюцинационный SYSTEM
cat opencode.json      # provider ollama, baseURL localhost:11434/v1, agent local-guide
cat system.txt         # промпт тестируемого агента
```

Ключевая деталь, которую стоит озвучить: эндпоинт `/v1/chat/completions`
(OpenAI-совместимый, который использует OpenCode) игнорирует Ollama-шный `think`,
поэтому отключение "размышлений" модели сделано через
`options.reasoningEffort: "none"` в `opencode.json` — без этого параметра
каждый ответ занимал 4–15 минут.

## 4. (Опционально) Показать пройденные тесты демо-сервиса

```bash
cd /mnt/c/Users/<user>/Documents/ITMO/ITMOv2/practices/practice_03
make test
# Standard library only: ready
# test_duplicate ... ok
# test_empty ... ok
# test_subscribe ... ok
# Ran 3 tests in 0.00Xs — OK
```

Это подтверждает, что сам демо-код корректен и расхождения в ответах модели
(см. таблицу в `REPORT.md`) — целиком на стороне интерпретации кода моделью, а не
баг в `demo/`.

## 5. Если что-то пошло не так во время демо

- **Долгий ответ (>2 минуты) на разогретой модели** — проверить
  `ollama ps`: возможно, модель успела выгрузиться. Перезапустить прогрев
  (шаг 0) и повторить запрос.
- **`opencode: command not found`** — `$PATH` обновляется через `~/.profile`,
  который читается только в login-шеллах. В обычной интерактивной сессии WSL
  (`wsl`, `bash -l`) всё работает; если команда запущена через неинтерактивный
  `bash -c "..."` (без `-l`), используйте полный путь `~/.opencode/bin/opencode`
  либо явно: `bash -lc "opencode ..."`.
- **Ошибка подключения к `localhost:11434`** — проверить
  `systemctl status ollama` и `sudo systemctl restart ollama`.
- **Запасной вариант при сбое сети/окружения** — заранее записанный скринкаст
  прогона (см. README практики, пункт "если совсем проблемы").
