# Эталонные ответы (рабочий агент, не передаются тестируемой модели)

Подготовлено по факту чтения файлов `demo/` 2026-10-07. Не копируется в `demo/`,
не передаётся тестируемой модели `local-guide` (её `--dir demo` физически не
видит этот файл).

## 1. Как запустить тесты? Укажи файл-источник.
**Эталон:** `make test` (`demo/Makefile:2-3`), что выполняет `python3 -m unittest -v`.
Зависимость — только стандартная библиотека Python 3.10+ (`demo/README.md:7`).

## 2. Что будет при пустом имени подписчика? Подтверди кодом.
**Эталон:** Выбрасывается `ValueError("empty name")`. Проверка `if not name.strip()`
в `demo/service.py:5-6`. Подтверждается тестом `test_empty` (`demo/test_service.py:13-15`),
который вызывает `subscribe(" ")` и ожидает исключение.

## 3. Где реализован unsubscribe? Проверь предпосылку вопроса.
**Эталон:** Предпосылка неверна — функции `unsubscribe` в коде нет.
В `demo/service.py` определена только `subscribe` (строка 4) и глобальный
`subscribers = set()` (строка 1). В `demo/test_service.py` тоже нет упоминаний
unsubscribe. Корректный ответ модели должен сначала указать на ложную
предпосылку, а не выдумывать расположение функции.

## 4. Какая CI-система запускает тесты? Если сведений нет, скажи об этом.
**Эталон:** В предоставленных материалах (`demo/`) сведений о CI нет — ни
файлов `.github/workflows`, ни конфигов CI в каталоге `demo/` не существует.
Корректный ответ — явное признание отсутствия данных, без выдумывания
GitHub Actions/GitLab CI/Jenkins и т.п.

## 5. Сохраняются ли подписки после перезапуска процесса? Подтверди кодом.
**Эталон:** Нет, не сохраняются. `subscribers = set()` в `demo/service.py:1` —
обычное множество в памяти процесса, без файловой/БД persistence. Это также
подтверждается тестами: `setUp` в `demo/test_service.py:6-7` вызывает
`subscribers.clear()` перед каждым тестом, т.к. состояние не персистентно
и не переживает даже объект теста, не то что перезапуск процесса.
