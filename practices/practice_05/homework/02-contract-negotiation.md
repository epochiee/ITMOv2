# ДЗ 5. Согласование контракта

Вход: `specs/001-changelog-preview-ui/spec.md` (UI, раздел «Ожидания от логики», 2 маркера NEEDS CLARIFICATION) и `specs/002-changelog-preview-api/spec.md` (логика, разделы «Предлагаемый контракт» и «Ожидания от UI», 3 маркера). Спеки сверялись по четырём осям из слайда: данные, вызовы, ошибки, состояния. Результат — [`changelog-gen/specs/contracts/changelog-preview-api.md`](../changelog-gen/specs/contracts/changelog-preview-api.md).

## Расхождения и решения

| # | Ось | UI ожидал | Логика предлагала | Решение |
|---|---|---|---|---|
| 1 | вызовы | «Сведения для экрана»: типы, диапазон по умолчанию, **имя репозитория**, доступность | `GET /api/meta`: типы, `default_range`, лимиты — без имени репозитория | `/api/meta` + поле `repository` (имя каталога без пути, FR-002 UI); при недоступном репозитории `/api/meta` отвечает `not_a_repository` (FR-025 UI) |
| 2 | вызовы | запрос только по явному действию (FR-008) | «по действию и/или с задержкой ~300 мс» | **Только явное действие**, без debounce: поведение экрана решает UI; одновременно ≤ 1 запроса |
| 3 | данные | «без фильтра» — признаком; все 10 отмечены = без фильтра | без фильтра — параметр не передаётся; `types=` — ошибка | Все отмечены → `types` не передаётся; часть → CSV; ни одного → запроса нет |
| 4 | данные | всего / в changelog / пропущено (MUST), список пропущенных с **коротким хэшем**, число breaking | `stats{total, included, filtered_out, skipped}`, `skipped[{header, reason}]` | Форма логики. Хэш и число breaking не передаём (UI держал их как «желательно»). Причину пустого результата UI выводит из `stats` |
| 5 | ошибки | `range_not_found`, `range_invalid`, `type_invalid`, `repo_unavailable`, `internal` | закрытый перечень из 10 кодов | Коды логики. Сопоставление: `range_not_found`→`unknown_range`, `range_invalid`→`invalid_range`, `type_invalid`→`invalid_types`, `repo_unavailable`→`not_a_repository` + `git_error`, `internal`→прочие коды и не-JSON |
| 6 | ошибки | — (не знал о лимите) | `range_too_large` (422) при > 1000 коммитах | Принято. UI показывает её **у поля диапазона**, как другие ошибки диапазона |
| 7 | состояния | репозиторий без коммитов → «Пустой результат», не ошибка | git отдаёт 128 → ошибка | **Решение в пользу UI**: при `range = HEAD` в репозитории без коммитов — 200 с пустым результатом (`total = 0`); другой диапазон там — `unknown_range` |
| 8 | ошибки | технические тексты не показывать (FR-024) | `message` — диагностика на английском | `message` только для разработчика; UI его не показывает |
| 9 | NEEDS CLARIFICATION UI FR-004 | подсказки тегов/веток? | — | **Нет**: свободный ввод с примерами; отдельного вызова не добавляем |
| 10 | NEEDS CLARIFICATION UI FR-015 / логика FR-017 | заголовок версии? | вход «версия»? | **Нет**: `## Unreleased`, как в CLI (в CLI тоже нет `--version`) |
| 11 | NEEDS CLARIFICATION логика FR-018 | — | структурированный список коммитов? | **Нет**: UI показывает Markdown буквально (FR-012 UI), разбирать его не нужно |
| 12 | NEEDS CLARIFICATION логика FR-016 | подсказка через 5 с (FR-011) | лимит N = 1000, ошибка без частичного результата | Принято как предложено |
| 13 | вызовы | файлы страницы определяет UI | `GET /` и «статические файлы» | Один `index.html` со встроенными CSS и JS |

Совпали без обсуждения: пустой диапазон → `HEAD`; breaking-коммиты всегда включены и это поясняется на экране; нераспознанные коммиты — не ошибка; `markdown` показывается и копируется буквально; ввод проверяется до git; при ошибке старый результат не показывается.

## Обновление спек

Каждой команде в её собственный чат отправлено: «Учти решения согласования (таблица), снимите маркеры NEEDS CLARIFICATION, замените свои разделы ожиданий ссылкой на контракт, перепроверьте чеклист». Итоги — `03-spec-updates.md`.
