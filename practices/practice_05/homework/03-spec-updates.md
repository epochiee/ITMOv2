# ДЗ 5. Обновление спек после согласования

Каждая команда правила свою спеку в своём чате (продолжение того же агента), по таблице решений из `02-contract-negotiation.md`. Спеку другой команды они по-прежнему не читали.

| | Команда 1 — UI | Команда 2 — логика |
|---|---|---|
| Было | 4 истории, 27 FR, раздел «Ожидания от логики» (Л-1…Л-5), 2 маркера NEEDS CLARIFICATION, чеклист 15/16 | 6 историй, 26 FR, «Предлагаемый контракт» + «Ожидания от UI», 3 маркера, чеклист 15/16 |
| Стало | статус `Agreed`, строка `Contract`, 0 маркеров, чеклист **16/16** | статус `Agreed`, строка `Contract`, 0 маркеров, чеклист **16/16** |
| Ключевые правки | FR-002/005/025 — данные из `/api/meta`; FR-004, FR-015 — маркеры сняты (#9, #10); FR-011 подсказка «Большая история» стала MUST; FR-013/016 — без хэша и числа breaking (#4); FR-019 — причина пустого результата по `stats` (#7); FR-020 — таблица по кодам контракта + `range_too_large` у поля (#5, #6); FR-024 — `message` не показывается (#8) | FR-002 — `repository` и `not_a_repository` в справочнике (#1); FR-008 — разрешён `+`; FR-014 — пустой репозиторий при `HEAD` = успех (#7); FR-016/017/018 — маркеры сняты (#12, #10, #11); FR-025 — один HTML (#13); разделы контракта заменены ссылкой на общий контракт (#2, #3, #8) |
| Дублирование | «Ожидания от логики» заменены разделом «Контракт с логикой» — ссылка, без пересказа | «Предлагаемый контракт» и «Ожидания от UI» заменены ссылками |

Итог: ни одна спека больше не описывает формат обмена сама — обе ссылаются на `specs/contracts/changelog-preview-api.md`. Это и есть «одна фича — один контракт»: изменение на стыке делается в одном месте.

Решение человека (делегировано): обе спеки приняты, можно планировать (`/speckit-plan`).
