# Сквозной сценарий UI (T106): браузер → changelog-gen-web → git

Стенд: `changelog-gen-web --port 8765` в демо-репозитории из 8 коммитов (`feat: initial release` + тег `v1.0`, `fix(parser)…`, `update stuff` — не по формату, `docs…`, `feat(cli)…`, `chore…`, `refactor(api)!…` — breaking, `feat(web): preview <changelog> & copy` — проверка буквального вывода). Браузер — встроенная панель Claude Code. Действия — настоящие клики и ввод с клавиатуры. Состояние экрана после каждого шага снималось скриптом из DOM: видимые зоны, тексты, фокус, `aria-invalid`.

Дефекты, найденные прогоном и исправленные (в браузере перепроверены шаги 3a–6b):

1. Пометка «Параметры изменены» жила внутри блока «Успех», поэтому после пустого результата не показывалась (FR-017). Перенесена на уровень области результата.
2. «В диапазоне 4 коммитов» — неверное склонение. Добавлена функция `commits(n)` (1 коммит / 2–4 коммита / 5+ коммитов).

Не проверялось в браузере, только pytest (`tests/test_web.py`): `not_a_repository` (блокирующий баннер зависит от 503 у `/api/meta`), `git_error/timeout`, `range_too_large`, `forbidden`. Чтобы воспроизвести эти ответы на живом стенде, пришлось бы ломать окружение.
