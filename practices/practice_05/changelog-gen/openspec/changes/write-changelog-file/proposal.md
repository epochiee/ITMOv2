# Proposal

## Why

После `--types` пользователь получает готовую секцию, но вставлять её в `CHANGELOG.md` по-прежнему приходится вручную или через `changelog-gen > tmp && cat tmp CHANGELOG.md > ...`. При такой склейке легко затереть файл: `changelog-gen > CHANGELOG.md` молча уничтожает историю. Skill `release-notes` тоже вставляет секцию руками.

## What Changes

- Новый флаг `--output FILE`: секция записывается в начало `FILE`, прежнее содержимое сохраняется после одной пустой строки. Если `FILE` не существует, он создаётся.
- С `--output` stdout пуст; в stderr печатается одна строка `wrote <FILE>`. Строки `skip:` в stderr сохраняются.
- Если коммитов нет (после фильтра или в диапазоне), файл не меняется, в stderr — `nothing to write`, код 0.
- Запись атомарная: при ошибке (нет каталога, нет прав) файл остаётся прежним, код 1, в stderr причина без трейсбека.
- `--output` сочетается с диапазоном и `--types`.

Не входит в изменение:

- заголовок версии вместо `Unreleased` (`--version`), дата релиза;
- проверка дублей (повторный запуск добавит секцию ещё раз);
- изменения skill `release-notes` и MCP-сервера.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `changelog-cli`: результат может уходить не только в stdout, но и в начало файла; меняются требования «Выбор диапазона коммитов» и «Пустой результат фильтра», добавляются требования о записи в файл и об ошибке записи.

## Impact

- Код: `src/changelog_gen/cli.py` (флаг, запись), возможно небольшой модуль записи.
- Тесты: `tests/test_cli.py`.
- Зависимости: нет.
