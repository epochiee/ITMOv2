# Proposal

## Why

`changelog-gen` выводит все распознанные коммиты, включая `docs`, `test`, `chore` и `ci`. Для заметок о выпуске пользователю нужны в основном `feat` и `fix`, и сейчас лишнее приходится вычищать руками. Кроме того, любой аргумент CLI уходит в `git log` как диапазон: `changelog-gen --types feat` падает с трейсбеком `CalledProcessError`.

## What Changes

- Новый флаг `--types TYPE[,TYPE...]`: в вывод попадают только коммиты перечисленных типов (и breaking-коммиты, см. ниже). Значения разделяются запятой, пробелы вокруг значений обрезаются. Повтор флага объединяет значения: `--types feat --types fix` ≡ `--types feat,fix`.
- Коммиты с breaking-изменением попадают в вывод независимо от `--types`, чтобы фильтр не скрыл ломающее изменение (так же поступают пресеты conventional-changelog).
- Неизвестный или пустой тип в `--types` — ошибка использования: код 2, в stderr недопустимое значение и список допустимых типов, stdout пуст, `git` не вызывается.
- CLI переходит на `argparse` (стандартная библиотека) без сокращений флагов. Позиционный диапазон и значение по умолчанию `HEAD` сохраняются.
- **BREAKING:** раньше первый аргумент целиком уходил в `git log`, поэтому недокументированно работали флаги git (`changelog-gen --no-merges`, `changelog-gen --since=2026-10-01`), а лишние аргументы молча игнорировались. Теперь неизвестные флаги и второй позиционный аргумент — ошибка использования (код 2). Совместимость с этими вызовами сознательно не сохраняем: документированный вызов — только `changelog-gen [RANGE]`. Вызов вида `changelog-gen -3` продолжит работать: `argparse` примет `-3` за позиционный диапазон.
- Без `--types` вывод не меняется: тот же Markdown, те же строки `skip:` в stderr, код 0.

Не входит в изменение:

- исключающий фильтр (`--exclude-types`), повторяемый флаг `--type`, фильтр по scope, настройка через файл;
- обработка неверного диапазона git (`changelog-gen nosuchref` по-прежнему падает с трейсбеком) — отдельная задача;
- изменения `parser`, `renderer`, MCP-сервера и skill `release-notes`.

## Capabilities

### New Capabilities

- `changelog-cli`: поведение командной строки `changelog-gen` — выбор диапазона коммитов, вывод Markdown в stdout, сообщения о пропущенных коммитах и фильтрация по типам.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спецификации (brownfield-проект, это первое изменение под OpenSpec). Прежнее поведение CLI, которое сохраняем, описано требованием в новой capability.

## Impact

- Код: `src/changelog_gen/cli.py` (разбор аргументов, фильтр). `parser.TYPES` переиспользуется как список допустимых типов.
- Тесты: `tests/test_cli.py` — новые тесты для `main()` на временном git-репозитории.
- Интерфейс: новый флаг `--types`; `main()` принимает необязательный список аргументов для тестов.
- Зависимости: новых нет (`argparse` из стандартной библиотеки).
