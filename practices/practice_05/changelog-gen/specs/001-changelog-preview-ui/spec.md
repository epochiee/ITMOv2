# Feature Specification: Экран предпросмотра changelog (UI)

**Feature Branch**: `001-changelog-preview-ui` (имя каталога спеки; отдельная git-ветка не создавалась)

**Created**: 2026-10-27

**Status**: Agreed

**Contract**: specs/contracts/changelog-preview-api.md

**Input**: User description: "Ты — команда 1 (UI). Опиши экран и действия пользователя, состояния (пусто, загрузка, успех, пустой результат, ошибка) и ошибки глазами пользователя. Формат API и правила валидации не решай. В конце спеки — раздел «Ожидания от логики»: какие данные, вызовы и ошибки нужны экрану. Код не пиши."

**Контекст**: фича «Локальный сервис предпросмотра changelog» из брифа ДЗ 5 (`homework/00-brief.md`). Разработчик запускает `changelog-gen-web`, открывает страницу, указывает диапазон коммитов и типы, видит готовую секцию changelog и копирует её. Эта спека описывает только UI: экран, действия, состояния и ошибки глазами пользователя. Данные, вызовы, коды ошибок и правила проверки ввода зафиксированы в общем контракте (см. раздел «Контракт с логикой»); спека ссылается на него и не пересказывает.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Предпросмотр и копирование changelog по диапазону (Priority: P1)

Разработчик запустил `changelog-gen-web` в каталоге своего репозитория и открыл страницу в браузере. Он вводит диапазон коммитов (например, `v1.0..HEAD`) или оставляет поле пустым, нажимает «Показать», видит готовую секцию changelog в Markdown и одним нажатием копирует её, чтобы вставить в `CHANGELOG.md` или в описание релиза.

**Why this priority**: это и есть ценность фичи — заменить запуск CLI с флагами и перенаправлением вывода одним экраном. Даже без ручного выбора типов (по умолчанию отмечены все) история даёт рабочий MVP.

**Independent Test**: на тестовом репозитории с известной историей открыть страницу, ввести диапазон, нажать «Показать», затем «Копировать»; вставленный из буфера обмена текст совпадает с выводом `changelog-gen <диапазон>` на той же истории.

**Acceptance Scenarios**:

1. **Given** страница только что открыта, **When** пользователь ещё ничего не нажимал, **Then** экран в состоянии «Пусто»: в шапке имя репозитория, поле диапазона пустое с подсказкой `HEAD`, отмечены все 10 типов, в области результата приглашение «Укажите диапазон и типы и нажмите „Показать“», кнопки «Копировать» нет, запрос за changelog не отправлялся.
2. **Given** поле диапазона пустое, **When** пользователь нажимает «Показать», **Then** экран проходит состояние «Загрузка» и показывает changelog по всем коммитам, достижимым из `HEAD`; в сводке над текстом указан применённый диапазон `HEAD`.
3. **Given** в поле введено `v1.0..HEAD`, **When** пользователь нажимает Enter в поле диапазона, **Then** происходит то же, что при нажатии «Показать», и в результат попадают только коммиты этого диапазона.
4. **Given** запрос отправлен и ответа ещё нет, **When** пользователь смотрит на экран, **Then** виден индикатор «Формируем changelog…», кнопка «Показать» недоступна, повторное нажатие или Enter второй запрос не отправляют, прежний результат скрыт и недоступен для копирования.
5. **Given** показан результат, **When** пользователь нажимает «Копировать», **Then** в буфер обмена попадает весь текст changelog ровно как показан (включая часть, невидимую без прокрутки), без сводки и предупреждений, а рядом с кнопкой примерно на 2 секунды появляется «Скопировано».
6. **Given** браузер не разрешил скопировать текст автоматически, **When** пользователь нажимает «Копировать», **Then** весь текст результата выделяется и появляется подсказка «Не удалось скопировать автоматически — нажмите Ctrl+C (⌘C на Mac)».
7. **Given** показан результат, **When** пользователь меняет диапазон или отметки типов, **Then** результат остаётся на экране с пометкой «Параметры изменены — нажмите „Показать“, чтобы обновить», а сводка по-прежнему показывает параметры, по которым он построен.

### User Story 2 — Фильтр по типам коммитов (Priority: P2)

Разработчик хочет видеть в changelog только часть типов — например, `feat` и `fix` для описания релиза. Он снимает лишние отметки в группе «Типы коммитов» и нажимает «Показать». Поведение фильтра совпадает с CLI: breaking-изменения не отфильтровываются никогда.

**Why this priority**: второй по частоте сценарий из брифа; без него пользователь вынужден вручную вычищать лишние строки из результата.

**Independent Test**: на истории `feat: add x`, `fix: bug`, `docs: readme`, `chore: deps`, `refactor(api)!: drop v1` отметить только `feat` и `fix` и нажать «Показать»; текст совпадает с выводом `changelog-gen --types feat,fix`: есть `add x`, `bug` и секция Breaking Changes со строкой про `drop v1`, нет `readme` и `deps`.

**Acceptance Scenarios**:

1. **Given** страница открыта, **When** пользователь смотрит на группу «Типы коммитов», **Then** он видит 10 переключателей в порядке feat, fix, docs, style, refactor, perf, test, build, ci, chore (все отмечены), кнопки «Все» и «Ничего» и постоянное пояснение «Breaking-изменения попадают в changelog всегда, независимо от выбранных типов».
2. **Given** отмечены только `feat` и `fix`, **When** пользователь нажимает «Показать», **Then** текст результата совпадает с выводом CLI `--types feat,fix` на той же истории, а сводка показывает «Типы: feat, fix».
3. **Given** в диапазоне есть breaking-коммит неотмеченного типа, **When** пользователь нажимает «Показать», **Then** этот коммит присутствует в секции Breaking Changes результата, и экран не показывает ни ошибки, ни предупреждения по этому поводу.
4. **Given** пользователь снял все отметки (вручную или кнопкой «Ничего»), **When** он смотрит на форму, **Then** кнопка «Показать» недоступна, у группы типов видна подсказка «Выберите хотя бы один тип», и ни кнопка, ни Enter в поле диапазона запрос не отправляют.
5. **Given** отмечены все типы, **When** пользователь нажимает «Показать», **Then** текст результата совпадает с выводом CLI без `--types`, а сводка показывает «Типы: все».

### User Story 3 — Понятные ошибки (Priority: P2)

Разработчик ошибся в диапазоне, выбрал слишком большой диапазон, сервис остановлен или репозиторий стал недоступен. По сообщению на экране он понимает, что не так и что сделать, не заглядывая в терминал и не видя технических подробностей.

**Why this priority**: без понятных ошибок пользователь возвращается к CLI; конституция (принцип V) запрещает показывать трейсбеки и внутренние пути.

**Independent Test**: по очереди ввести несуществующий тег, значение, похожее на опцию (`--all`), диапазон больше 1000 коммитов, остановить сервис при открытой странице, сделать репозиторий недоступным после запуска сервиса; для каждого случая на экране своё сообщение с причиной и следующим действием, введённые значения сохранены.

**Acceptance Scenarios**:

1. **Given** введён диапазон `v9.9..HEAD`, а тега `v9.9` в репозитории нет, **When** пользователь нажимает «Показать», **Then** под полем диапазона появляется «Не удалось найти „v9.9..HEAD“ в репозитории. Проверьте имя тега, ветки или коммита.», поле подсвечено, фокус переведён в поле, введённое значение и отметки типов сохранены, результата на экране нет.
2. **Given** введено `--all`, **When** пользователь нажимает «Показать», **Then** под полем диапазона появляется «Диапазон не может начинаться с „-“. Примеры: v1.0..HEAD, main, HEAD~10..HEAD.», и никакие данные из истории не показаны.
3. **Given** в выбранном диапазоне больше 1000 коммитов, **When** пользователь нажимает «Показать», **Then** под полем диапазона появляется «В диапазоне больше 1000 коммитов. Сузьте диапазон, например v1.0..HEAD.», частичного результата нет.
4. **Given** сервис остановили после открытия страницы, **When** пользователь нажимает «Показать», **Then** над областью результата появляется баннер «Нет связи с сервисом. Убедитесь, что changelog-gen-web запущен, и нажмите „Повторить“.»; кнопка «Повторить» повторяет последний запрос с теми же параметрами.
5. **Given** репозиторий стал недоступен после запуска сервиса, **When** пользователь открывает страницу или нажимает «Показать», **Then** виден блокирующий баннер «Репозиторий недоступен. Перезапустите changelog-gen-web из каталога git-репозитория.», форма недоступна.
6. **Given** сервис вернул ошибку, не относящуюся к вводу, неизвестный код или ответ, который экран не может понять, **When** экран обрабатывает ответ, **Then** виден баннер «Не удалось сформировать changelog. Подробности — в терминале, где запущен сервис.» с кнопкой «Повторить»; на экране нет трейсбека, путей файловой системы, сырого вывода git и диагностического текста сервиса.
7. **Given** под полем диапазона показана ошибка, **When** пользователь меняет значение поля, **Then** сообщение и подсветка поля исчезают сразу, не дожидаясь нового запроса.

### User Story 4 — Пустой результат и пропущенные коммиты (Priority: P3)

Разработчик получил ответ, в котором нечего показывать, или часть коммитов не попала в changelog, потому что оформлена не по Conventional Commits. Экран объясняет, почему так вышло, и не выдаёт это за ошибку.

**Why this priority**: без объяснения пустой экран выглядит как сбой; но сценарий вторичен по отношению к получению результата и исправлению ошибок.

**Independent Test**: на заранее подготовленных историях (пустой диапазон; репозиторий без коммитов; только `docs: readme` при фильтре `feat`; только `update stuff`; `update stuff` + `fix: bug`) нажать «Показать» и проверить текст состояния, наличие/отсутствие кнопки «Копировать» и предупреждение о пропущенных коммитах.

**Acceptance Scenarios**:

1. **Given** в диапазоне нет ни одного коммита (например, `HEAD..HEAD`), **When** пользователь нажимает «Показать», **Then** экран в состоянии «Пустой результат»: «В диапазоне „HEAD..HEAD“ нет коммитов. Проверьте границы диапазона.»; кнопки «Копировать» нет; оформление не как у ошибки.
2. **Given** в репозитории ещё нет коммитов, а поле диапазона пустое, **When** пользователь нажимает «Показать», **Then** экран показывает «Пустой результат» с текстом «В диапазоне „HEAD“ нет коммитов. Проверьте границы диапазона.», а не ошибку.
3. **Given** в диапазоне только `docs: readme`, а отмечен только `feat`, **When** пользователь нажимает «Показать», **Then** экран показывает «Нет коммитов выбранных типов. В диапазоне 1 коммит других типов.» и кнопку «Выбрать все типы и показать», которая отмечает все типы и сразу отправляет запрос.
4. **Given** все коммиты диапазона оформлены не по Conventional Commits (например, `update stuff`), **When** пользователь нажимает «Показать», **Then** экран показывает «Ни один коммит в диапазоне не оформлен по Conventional Commits» и список заголовков пропущенных коммитов.
5. **Given** в диапазоне `update stuff` и `fix: bug`, **When** пользователь нажимает «Показать», **Then** результат содержит `- bug`, а над текстом видно предупреждение «Пропущено коммитов не по формату: 1» с раскрывающимся списком, где есть `update stuff`; предупреждение не мешает копированию и не попадает в копируемый текст.

### Edge Cases

- **Пустое поле или только пробелы** → используется диапазон по умолчанию (`HEAD`); сводка показывает применённый диапазон из ответа.
- **Значение похоже на опцию git** (`--all`, `-n5`) → ошибка недопустимого диапазона под полем; экран не пытается «исправить» ввод сам.
- **Пробел или управляющий символ внутри значения** (`v1.0 ..HEAD`) → ошибка недопустимого диапазона под полем с указанием причины.
- **Значение длиннее 200 символов** → ошибка недопустимого диапазона «Диапазон длиннее 200 символов»; в тексте ошибки само значение сокращается примерно до 40 символов с «…».
- **Несуществующий тег или опечатка в имени ветки** → ошибка «не найден» под полем.
- **Диапазон без коммитов** (`HEAD..HEAD`, `v1.0..v1.0`) → «Пустой результат», не ошибка.
- **Репозиторий без единого коммита и пустое поле** → «Пустой результат» по причине (а) из FR-019; любой другой диапазон в таком репозитории — ошибка «не найден».
- **В диапазоне больше 1000 коммитов** → ошибка у поля диапазона, частичного результата нет.
- **Сняты все типы** → «Показать» недоступна, запрос не уходит.
- **Breaking-коммит неотмеченного типа** → присутствует в секции Breaking Changes.
- **Спецсимволы в сообщениях коммитов** (`<script>`, `**`, `&amp;`, обратные кавычки) → показываются и копируются буквально, ничего не интерпретируется и не выполняется.
- **Кириллица и emoji в сообщениях** → показываются и копируются без искажений.
- **Очень большой результат** (сотни строк) → текст прокручивается внутри своей области; «Копировать» копирует весь текст.
- **Долгая загрузка** → через 5 секунд к индикатору добавляется «Большая история — это может занять время»; экран не обрывает ожидание сам. Если git не уложился в отведённое сервисом время, показывается баннер ошибки git с «Повторить».
- **Сервис остановлен после открытия страницы** → баннер «Нет связи с сервисом».
- **Пользователь меняет поля во время загрузки** → пришедший результат показывается с пометкой «Параметры изменены».
- **Повторные нажатия «Показать» или Enter во время загрузки** → игнорируются.
- **Страница открыта в двух вкладках** → вкладки работают независимо друг от друга.
- **Перезагрузка страницы** → экран возвращается в «Пусто» со значениями по умолчанию.
- **Репозиторий изменился между двумя «Показать»** (новый коммит) → второй результат отражает текущее состояние; экран ничего не кэширует.

## Requirements *(mandatory)*

### Состав экрана

Экран — одна страница из четырёх зон:

1. **Шапка**: название «Предпросмотр changelog» и имя репозитория (имя каталога, без полного пути), с которым работает сервис.
2. **Форма параметров**: поле «Диапазон коммитов» с подсказкой `HEAD` и примерами под полем (`v1.0..HEAD`, `main`, `HEAD~10..HEAD`); группа «Типы коммитов» — 10 переключателей, кнопки «Все» и «Ничего», пояснение про breaking-изменения; кнопка «Показать».
3. **Область результата**: строка сводки, предупреждение о пропущенных коммитах (если есть), текст changelog моноширинным шрифтом как есть, кнопка «Копировать».
4. **Сообщения**: ошибки, относящиеся к полю, — у этого поля; общие ошибки — баннером над областью результата.

### Состояния экрана

| Состояние | Когда | Что видит пользователь | Доступные действия |
|-----------|-------|------------------------|--------------------|
| Пусто | страница открыта, справочные сведения получены, запросов за changelog ещё не было | форма со значениями по умолчанию, приглашение «Укажите диапазон и типы и нажмите „Показать“» | ввести диапазон, изменить типы, «Показать» |
| Загрузка | запрос отправлен, ответа нет | индикатор «Формируем changelog…»; через 5 с — «Большая история — это может занять время» | менять поля (запрос не отменяется); «Показать» недоступна; «Копировать» нет |
| Успех | ответ получен, в changelog ≥ 1 коммита | сводка, текст changelog, «Копировать», предупреждение о пропущенных (если есть) | «Копировать», изменить параметры и «Показать» |
| Пустой результат | ответ получен, в changelog 0 коммитов | объяснение причины и совет (см. FR-019), без оформления ошибки | «Выбрать все типы и показать» (если причина в фильтре), изменить параметры |
| Ошибка | сервис вернул ошибку, ответа нет или ответ непонятен | сообщение у поля или баннер с причиной и действием (см. FR-020) | исправить поле и «Показать»; «Повторить» |

### Functional Requirements

**Открытие и ввод**

- **FR-001**: Экран MUST открываться по адресу, который сервис сообщает при запуске, и показывать форму и область результата в состоянии «Пусто», не запрашивая changelog автоматически.
- **FR-002**: Экран MUST показывать в шапке имя репозитория, с которым работает сервис, — значение `repository` из справочника `/api/meta` (имя каталога, без пути).
- **FR-003**: Поле «Диапазон коммитов» MUST принимать произвольный текст и отправлять его как введён; пустое поле означает диапазон по умолчанию, который подсказка поля показывает как `HEAD`. Экран MUST NOT сам проверять или изменять значение диапазона — допустимость решает логика по правилам контракта, экран показывает её вердикт.
- **FR-004**: Диапазон вводится только вручную; под полем MUST показываться примеры (`v1.0..HEAD`, `main`, `HEAD~10..HEAD`). Подсказок из списка тегов и веток репозитория нет.
- **FR-005**: Группа «Типы коммитов» MUST содержать по одному переключателю на каждый тип из справочника `/api/meta` в его порядке (сейчас feat, fix, docs, style, refactor, perf, test, build, ci, chore); при открытии страницы все отмечены. Кнопка «Все» MUST отмечать все типы, «Ничего» — снимать все отметки.
- **FR-006**: Рядом с группой типов MUST постоянно отображаться пояснение, что breaking-изменения попадают в changelog независимо от выбранных типов.
- **FR-007**: Если не отмечен ни один тип, кнопка «Показать» MUST быть недоступна, у группы MUST показываться подсказка «Выберите хотя бы один тип», и запрос MUST NOT отправляться ни кнопкой, ни клавишей Enter.
- **FR-008**: Запрос MUST отправляться только по нажатию «Показать», Enter в поле диапазона, «Повторить» или «Выбрать все типы и показать»; само изменение полей запрос MUST NOT отправлять (без автозапросов и отложенной отправки).
- **FR-009**: При отмеченных всех типах экран MUST запрашивать changelog без фильтра (результат совпадает с CLI без `--types`), при части отмеченных — с перечнем этих типов (результат совпадает с CLI с `--types`). Как именно передаётся выбор — по контракту; фильтрует логика.

**Загрузка**

- **FR-010**: Сразу после отправки запроса экран MUST показать индикатор «Формируем changelog…», сделать «Показать» недоступной и убрать из области результата прежний результат и прежние ошибки. Одновременно MUST выполняться не более одного запроса за changelog.
- **FR-011**: Если ответа нет дольше 5 секунд, индикатор MUST дополняться текстом «Большая история — это может занять время». Экран MUST NOT сам прерывать ожидание.

**Успех**

- **FR-012**: В состоянии «Успех» экран MUST показывать текст changelog в точности как его вернула логика: моноширинным шрифтом, с сохранёнными переносами и пустыми строками, без интерпретации Markdown или HTML. Любые символы из сообщений коммитов MUST отображаться буквально.
- **FR-013**: Над текстом MUST показываться сводка: применённый диапазон, применённые типы («все» или перечень) и число коммитов, попавших в changelog.
- **FR-014**: Кнопка «Копировать» MUST помещать в буфер обмена весь текст changelog ровно как показан, без сводки и предупреждений, и показывать подтверждение «Скопировано» примерно на 2 секунды. Если автоматическое копирование недоступно, экран MUST выделить весь текст и показать подсказку про Ctrl+C / ⌘C.
- **FR-015**: Заголовок секции changelog всегда `## Unreleased`, как в CLI; он показывается и копируется вместе с текстом. Поля для имени версии и варианта копирования без заголовка нет.
- **FR-016**: Если в диапазоне есть коммиты не по Conventional Commits, экран MUST показывать предупреждение с их числом и раскрывающийся список их заголовков (первая строка сообщения; без хэша и без технической причины пропуска). Предупреждение MUST NOT мешать копированию и MUST NOT попадать в копируемый текст.
- **FR-017**: Если пользователь изменил параметры после отправки запроса или после получения результата, результат MUST оставаться на экране с пометкой «Параметры изменены — нажмите „Показать“, чтобы обновить»; сводка MUST показывать параметры, по которым результат построен.
- **FR-018**: Длинный результат MUST прокручиваться внутри своей области; форма, сводка и кнопка «Копировать» MUST оставаться доступными без прокрутки текста до конца.

**Пустой результат**

- **FR-019**: Если в changelog не попал ни один коммит, экран MUST показать состояние «Пустой результат» (не ошибку) без кнопки «Копировать». Причину экран MUST определять по счётчикам ответа (`stats`) в порядке, заданном контрактом (п. 4):
  (а) в диапазоне нет коммитов (`total = 0`, в том числе репозиторий без коммитов при диапазоне `HEAD`) — «В диапазоне „{диапазон}“ нет коммитов. Проверьте границы диапазона.»;
  (б) все коммиты не по формату (`skipped = total > 0`) — «Ни один коммит в диапазоне не оформлен по Conventional Commits» и список заголовков пропущенных;
  (в) иначе — нет коммитов выбранных типов — «Нет коммитов выбранных типов. В диапазоне {filtered_out} коммитов других типов.» и кнопка «Выбрать все типы и показать».

**Ошибки**

- **FR-020**: Экран MUST различать ошибки по кодам контракта (п. 5) и для каждой показывать собственный текст с причиной и следующим действием:

  | Код или ситуация | Где показывает экран | Текст для пользователя |
  |------------------|----------------------|------------------------|
  | `invalid_range` | под полем диапазона | по `details.rule`: `leading_dash` — «Диапазон не может начинаться с „-“.»; `whitespace` — «В диапазоне не должно быть пробелов.»; `control_char` — «В диапазоне есть недопустимые символы.»; `too_long` — «Диапазон длиннее {max_length} символов.»; во всех случаях добавляется «Примеры: v1.0..HEAD, main, HEAD~10..HEAD.» |
  | `unknown_range` | под полем диапазона | «Не удалось найти „{диапазон}“ в репозитории. Проверьте имя тега, ветки или коммита.» |
  | `range_too_large` | под полем диапазона | «В диапазоне больше {limit} коммитов. Сузьте диапазон, например v1.0..HEAD.» |
  | `invalid_types` | у группы типов | «Сервис не принял тип „{invalid}“. Обновите страницу.» |
  | `not_a_repository` | блокирующий баннер страницы, форма недоступна | «Репозиторий недоступен. Перезапустите changelog-gen-web из каталога git-репозитория.» |
  | `git_error` | баннер с «Повторить» | по `details.reason`: `timeout` — «git не ответил вовремя. Попробуйте сузить диапазон или повторить.»; `not_found` — «git не найден на этом компьютере.»; `failed` — «Не удалось прочитать историю git.» |
  | `invalid_request`, `forbidden`, `not_found`, `method_not_allowed`, неизвестный код, ответ не в ожидаемом формате | баннер с «Повторить» | «Не удалось сформировать changelog. Подробности — в терминале, где запущен сервис.» |
  | нет ответа (сеть) — определяет экран | баннер с «Повторить» | «Нет связи с сервисом. Убедитесь, что changelog-gen-web запущен, и нажмите „Повторить“.» |

- **FR-021**: Ошибки диапазона (`invalid_range`, `unknown_range`, `range_too_large`) MUST показываться под полем диапазона с подсветкой поля и переводом фокуса в него; `invalid_types` — у группы типов; остальные — баннером над областью результата. Кнопка «Повторить» MUST повторять последний запрос с теми же параметрами.
- **FR-022**: При любой ошибке введённое значение диапазона и отметки типов MUST сохраняться, а прежний результат MUST NOT показываться, чтобы пользователь не скопировал устаревший текст.
- **FR-023**: Сообщение у поля MUST исчезать, как только пользователь меняет значение этого поля; баннер (кроме блокирующего) — при отправке нового запроса.
- **FR-024**: Экран MUST NOT показывать диагностический текст ошибки из ответа сервиса (`message`), трейсбеки, пути файловой системы и сырой вывод git. Тексты строятся только по коду и деталям ошибки. Экран MAY показывать код ошибки мелким шрифтом, чтобы на него можно было сослаться.
- **FR-025**: Если справочник `/api/meta` при открытии страницы вернул `not_a_repository`, экран MUST сразу показать блокирующий баннер (FR-020), не дожидаясь нажатия «Показать». Если справочник не получен по другой причине, экран MUST показать соответствующий баннер из FR-020 с «Повторить», повторяющей запрос справочника.
- **FR-026**: Если код ошибки экрану неизвестен или ответ не удаётся понять, экран MUST показать общее сообщение о внутренней ошибке с кнопкой «Повторить».

**Доступность**

- **FR-027**: Все действия MUST выполняться с клавиатуры (переход между элементами, переключение типов, «Показать» по Enter, «Копировать»). Смена состояния (загрузка, успех, пустой результат, ошибка, «Скопировано») SHOULD сообщаться программам экранного доступа.

### Key Entities

- **Параметры предпросмотра**: диапазон (строка ровно как введена; пустая — диапазон по умолчанию) и набор отмеченных типов (непустое подмножество; все отмеченные — без фильтра).
- **Справочник экрана**: имя репозитория, список типов в каноническом порядке, диапазон по умолчанию (контракт, п. 3).
- **Результат предпросмотра**: текст секции changelog; применённые диапазон и типы; счётчики — всего в диапазоне, в changelog, отсеяно фильтром, пропущено; список пропущенных коммитов (контракт, п. 4).
- **Пропущенный коммит**: заголовок (первая строка сообщения); причина пропуска экраном не показывается.
- **Ошибка**: код, к какому полю относится (диапазон, типы или общая) и детали для текста сообщения (контракт, п. 5).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Разработчик, впервые открывший страницу, получает в буфере обмена changelog для нужного диапазона не более чем за 4 действия (ввести диапазон, при необходимости изменить типы, «Показать», «Копировать») и не дольше чем за 30 секунд.
- **SC-002**: На всех приёмочных историях (US1–US4) текст, скопированный с экрана, в 100 % случаев побайтно совпадает с выводом `changelog-gen` с теми же диапазоном и типами на той же истории.
- **SC-003**: Для истории до 1000 коммитов результат появляется на экране не позднее чем через 2 секунды после нажатия «Показать»; индикатор загрузки появляется без заметной задержки (не позже 0,2 секунды).
- **SC-004**: Для каждой строки таблицы ошибок FR-020 пользователь видит сообщение, в котором названы причина и следующее действие; 0 сообщений содержат трейсбек, путь файловой системы, сырой вывод git или диагностический текст сервиса.
- **SC-005**: Каждое из пяти состояний (пусто, загрузка, успех, пустой результат, ошибка) воспроизводится отдельным приёмочным сценарием и имеет собственный текст; ни в одном сценарии пустой результат не показан как ошибка, а ошибка — как пустой результат.
- **SC-006**: Ни в одном приёмочном сценарии повторное нажатие «Показать» или Enter во время загрузки не приводит ко второму запросу или к двойному выводу результата.
- **SC-007**: Для результата длиной 500 строк и более в буфер обмена попадает полный текст (0 потерянных строк).

## Assumptions

- Один пользователь, локальная машина, без авторизации; страница открывается в обычном настольном браузере (окно от ~1024 px шириной) без установки дополнительных программ и без отдельного шага сборки (ограничения брифа).
- Репозиторий — тот, в каталоге которого запущен `changelog-gen-web`; выбор другого репозитория на экране — вне рамок фичи.
- Страница не запрашивает changelog автоматически при открытии: пользователь сначала видит состояние «Пусто» и сам нажимает «Показать».
- Результат показывается как Markdown-текст — ровно то, что будет скопировано; отрисовка «как будет выглядеть» (отрендеренный Markdown) — вне рамок.
- Подсказки тегов и веток, заголовок версии и копирование без заголовка — вне рамок (решения согласования).
- Тексты интерфейса — зона ответственности UI; логика передаёт код ошибки и детали, а не фразы для пользователя.
- Язык интерфейса — русский; тексты в этой спеке — эталонные формулировки. Переключение языка — вне рамок.
- Параметры между перезагрузками страницы не сохраняются; запись в `CHANGELOG.md`, скачивание файла и история запросов — вне рамок.
- Время показа «Скопировано» (2 с) — разумное значение по умолчанию, его можно уточнить без изменения смысла требований.

## Контракт с логикой

Вызовы, данные ответов, коды ошибок, правила проверки диапазона и соответствие состояний экрана ответам зафиксированы в общем контракте [`specs/contracts/changelog-preview-api.md`](../contracts/changelog-preview-api.md). Всё, что раньше было предположениями Л-1…Л-5, решено там.
