## User Scenarios & Testing *(mandatory)*

Действующее лицо — разработчик, который запустил сервис `changelog-gen-web` в каталоге своего git-репозитория и обращается к нему через страницу (клиент команды 1) или напрямую. Во всех сценариях, если не сказано иное, используется эталонная история (от старых к новым): `fix: bug`, `update stuff`, `docs: readme`, `feat(api): add x`, `refactor(core)!: drop v1` — та же, что в характеризационном тесте CLI.

### User Story 1 - Секция changelog для диапазона (Priority: P1)

Разработчик указывает диапазон коммитов (или оставляет его пустым) и получает готовую Markdown-секцию changelog — ровно такую, какую напечатал бы CLI, — а также сводку: сколько коммитов прочитано, включено и пропущено.

**Why this priority**: Это ядро фичи: без него предпросмотр не имеет смысла. Одной этой истории достаточно, чтобы заменить запуск CLI с перенаправлением вывода.

**Independent Test**: Создать репозиторий с эталонной историей, запустить сервис, выполнить операцию «Построить секцию» без входных данных и с диапазоном; сравнить результат с выводом `changelog-gen` на той же истории.

**Acceptance Scenarios**:

1. **Given** репозиторий с эталонной историей, **When** выполняется «Построить секцию» без диапазона и без типов, **Then** текст секции совпадает с stdout `changelog-gen` (`## Unreleased`, секции Breaking Changes, Features, Fixes, Other), эффективный диапазон — `HEAD`, сводка: прочитано 5, включено 4, отфильтровано 0, пропущено 1.
2. **Given** та же история, **When** диапазон `HEAD~2..HEAD`, **Then** секция содержит `add x` и `drop v1` и не содержит `bug` и `readme`.
3. **Given** та же история, **When** диапазон передан с пробелами по краям (`"  HEAD~2..HEAD "`), **Then** результат тот же, что для `HEAD~2..HEAD`, а эффективный диапазон возвращается без пробелов.
4. **Given** та же история, **When** диапазон — пустая строка или строка из пробелов, **Then** используется `HEAD`, результат совпадает со сценарием 1.
5. **Given** та же история, **When** диапазон `HEAD..HEAD` (в нём нет коммитов), **Then** операция успешна, текст секции равен `## Unreleased` и переводу строки, включено 0 коммитов.
6. **Given** коммит `feat: добавить экспорт`, **When** строится секция, **Then** строка `- добавить экспорт` передаётся без искажения символов.

### User Story 2 - Фильтр по типам, как в CLI (Priority: P1)

Разработчик выбирает типы коммитов и видит только их — плюс breaking-изменения любого типа. Правила фильтра те же, что у `changelog-gen --types`.

**Why this priority**: Фильтр — вторая половина запроса из брифа; расхождение с CLI даст разные changelog для одной истории.

**Independent Test**: На эталонной истории выполнить «Построить секцию» с разными наборами типов и сравнить с выводом `changelog-gen --types …`.

**Acceptance Scenarios**:

1. **Given** эталонная история, **When** типы `feat,fix`, **Then** секция содержит `- **api**: add x`, `- bug` и секцию Breaking Changes с `- **core**: drop v1`, не содержит `readme`; в пропущенных — `update stuff`.
2. **Given** эталонная история, **When** типы `" feat , fix "`, **Then** результат совпадает со сценарием 1.
3. **Given** эталонная история, **When** типы переданы двумя отдельными значениями `feat` и `fix`, **Then** результат совпадает со сценарием 1 (значения объединяются).
4. **Given** эталонная история, **When** типы `feat`, **Then** секция содержит `### Breaking Changes` со строкой `- **core**: drop v1` (тип `refactor` не выбран, но коммит breaking) и `- **api**: add x`; сводка: прочитано 5, включено 2, отфильтровано 2, пропущено 1.
5. **Given** история только из `docs: readme`, **When** типы `feat`, **Then** операция успешна, текст секции — `## Unreleased` и перевод строки.
6. **Given** любая история и любой допустимый вход, **When** результат сервиса сравнивается с выводом `changelog-gen [RANGE] --types T`, **Then** текст секции совпадает (с точностью до перевода строк ОС), а причины пропуска совпадают со строками `skip:` CLI в том же порядке.

### User Story 3 - Ввод не становится опцией или путём git (Priority: P1)

Ввод приходит по сети, поэтому сервис проверяет его до обращения к git и гарантирует, что строка диапазона никогда не будет воспринята git как опция или как путь к файлу. Проверено: `git log --format=%B%x00 --output=pwned.txt` создаёт файл в рабочем каталоге, а `changelog-gen -- --output=x` делает то же через CLI; строка `src` (имя каталога) в CLI превращается в фильтр по пути, а не в ошибку.

**Why this priority**: Требование конституции (принцип V «Safe local surface»); нарушение позволяет перезаписать файлы на машине разработчика запросом со страницы.

**Independent Test**: Отправить набор «опасных» значений диапазона и типов и проверить: получена ошибка проверки, git не вызывался, ни один файл в каталоге репозитория не изменился.

**Acceptance Scenarios**:

1. **Given** любой репозиторий, **When** диапазон `--output=x.txt`, **Then** ошибка «недопустимый диапазон», git не вызывается, файл `x.txt` не создаётся.
2. **Given** любой репозиторий, **When** диапазон `-p` или `-3`, **Then** ошибка «недопустимый диапазон».
3. **Given** любой репозиторий, **When** диапазон содержит пробел, табуляцию, перевод строки или нулевой символ внутри (`HEAD --all`, `HEAD\n--all`), **Then** ошибка «недопустимый диапазон».
4. **Given** любой репозиторий, **When** диапазон длиннее 200 символов, **Then** ошибка «недопустимый диапазон».
5. **Given** в рабочем каталоге есть каталог `src`, а ревизии `src` нет, **When** диапазон `src`, **Then** ошибка «диапазон не найден» (а не changelog по коммитам, затронувшим `src/`).
6. **Given** любой каталог, **When** типы `feat,feature`, `""`, `feat,` или `FEAT`, **Then** ошибка «недопустимые типы» с недопустимым значением и полным списком допустимых типов; git не вызывается.
7. **Given** любой репозиторий, **When** в запросе есть неизвестный параметр (например, опечатка `type` вместо `types`) или диапазон передан дважды, **Then** ошибка «некорректный запрос»; фильтр молча не игнорируется.
8. **Given** запущенный сервис, **When** приходит запрос с чужим адресом назначения (например, `evil.example:<порт>`), **Then** ошибка «запрещено», git не вызывается.
9. **Given** запущенный сервис, **When** к нему обращаются по внешнему сетевому адресу машины, **Then** соединение не устанавливается (сервис слушает только `127.0.0.1`).

### User Story 4 - Понятные ошибки git и окружения (Priority: P2)

Если диапазон не существует, репозиторий пуст или недоступен, разработчик получает ошибку с машинным кодом, а не трейсбек (сейчас CLI на неверном диапазоне падает с `CalledProcessError`). Сервис после ошибки продолжает работать.

**Why this priority**: Опечатка в имени тега — самая частая ошибка пользователя; без понятного кода UI не сможет подсказать, что исправить.

**Independent Test**: Выполнить «Построить секцию» с несуществующей ревизией, в пустом репозитории и после удаления репозитория; убедиться, что коды ошибок верны, в ответе нет трейсбека и путей, а следующий корректный запрос успешен.

**Acceptance Scenarios**:

1. **Given** эталонная история, **When** диапазон `nope` или `v9.9..HEAD` (тега нет), **Then** ошибка «диапазон не найден»; сообщение не содержит трейсбека, абсолютных путей и сырого вывода git.
2. **Given** ветка без upstream, **When** диапазон `@{u}`, **Then** ошибка «диапазон не найден».
3. **Given** диапазон указывает не на коммит (`HEAD:README`), **When** строится секция, **Then** ошибка «диапазон не найден».
4. **Given** репозиторий без единого коммита, **When** диапазон не задан (эффективный `HEAD`), **Then** операция успешна: текст секции `## Unreleased` и перевод строки, прочитано 0, включено 0.
5. **Given** репозиторий без единого коммита, **When** диапазон отличен от `HEAD` (например, `main` или `HEAD~1..HEAD`), **Then** ошибка «диапазон не найден».
6. **Given** каталог не является git-репозиторием (или порт уже занят, или передан неизвестный параметр запуска), **When** разработчик запускает `changelog-gen-web`, **Then** сервис не стартует, печатает понятное сообщение без трейсбека и завершается с ненулевым кодом, порт не открывается.
7. **Given** сервис запущен, а затем каталог перестал быть репозиторием, **When** строится секция или запрашивается «Справочник», **Then** ошибка «нет репозитория».
8. **Given** любая из ошибок выше, **When** следом выполняется корректный запрос (после восстановления условий), **Then** он успешен — сервис не падает.

### User Story 5 - Большой диапазон (Priority: P2)

Если в диапазоне слишком много коммитов, сервис не зависает и не отдаёт огромный ответ, а сообщает, что диапазон нужно сузить.

**Why this priority**: Диапазон по умолчанию `HEAD` в большом репозитории означает всю историю; без ограничения первый же запрос может занять минуты.

**Independent Test**: Создать репозиторий с числом коммитов на границе лимита и на единицу больше; проверить успех и ошибку соответственно, а также что время ответа не растёт с размером всей истории.

**Acceptance Scenarios**:

1. **Given** в диапазоне ровно N коммитов (N — лимит, см. FR-016), **When** строится секция, **Then** операция успешна.
2. **Given** в диапазоне N + 1 коммит и больше, **When** строится секция, **Then** ошибка «диапазон слишком большой» со значением лимита; частичный changelog не возвращается.
3. **Given** репозиторий в 100 раз больше лимита, **When** диапазон `HEAD`, **Then** ошибка возвращается так же быстро, как успешный ответ на диапазон из N коммитов.

### User Story 6 - Страница и справочник для клиента (Priority: P3)

Браузер получает страницу клиента с того же адреса, что и операции, а клиент узнаёт у сервиса имя репозитория, список допустимых типов, диапазон по умолчанию и лимиты, чтобы не дублировать их у себя и сразу увидеть, доступен ли репозиторий.

**Why this priority**: Удобство и защита от рассинхронизации списка типов; без этой операции клиент может захардкодить список из `parser.TYPES`.

**Independent Test**: Выполнить операцию «Справочник» и сравнить список типов с `parser.TYPES`, а имя репозитория — с именем каталога корня; удалить репозиторий после старта и проверить ошибку.

**Acceptance Scenarios**:

1. **Given** запущенный сервис, **When** выполняется «Справочник», **Then** возвращаются имя каталога корня репозитория (без пути, например `changelog-gen`, в том числе при запуске из подкаталога), типы `feat, fix, docs, style, refactor, perf, test, build, ci, chore` в этом порядке, диапазон по умолчанию `HEAD`, максимальная длина диапазона 200 и лимит N.
2. **Given** сервис запущен, а затем каталог перестал быть репозиторием, **When** выполняется «Справочник», **Then** ошибка «нет репозитория».
3. **Given** запущенный сервис, **When** браузер открывает корневой адрес сервиса, **Then** возвращается страница клиента — один HTML-документ со встроенными стилями и скриптом — с того же адреса, что и операции.

### Edge Cases

- **Диапазон начинается с `-`** (`--output=x`, `-p`, `-3`, `--all`): `git log` принимает такие строки как опции, `--output` пишет файл. Сервис отклоняет их на этапе проверки (FR-008) и дополнительно передаёт диапазон в git только как ревизию (FR-009). Отличие от CLI: там `-3` проходит как «последние 3 коммита».
- **Диапазон совпадает с именем файла или каталога** (`src`, `README`): в CLI это становится фильтром по пути и тихо даёт другой changelog; сервис отвечает «диапазон не найден».
- **Пробелы, переводы строк, управляющие и нулевые символы** внутри диапазона: отклоняются (FR-008). Пробелы по краям обрезаются.
- **Пустой диапазон**: подставляется `HEAD`.
- **Диапазон без коммитов** (`HEAD..HEAD`, `^v1`): успешный ответ с секцией из одного заголовка, не ошибка.
- **Ревизия не существует, нет upstream, ревизия — не коммит**: «диапазон не найден».
- **Репозиторий без коммитов**: при эффективном диапазоне `HEAD` (в том числе пустом вводе) — успех с пустым результатом (прочитано 0); любой другой диапазон — «диапазон не найден».
- **Запуск вне git-репозитория**: сервис не стартует. Репозиторий исчез после старта: «нет репозитория» и для «Построить секцию», и для «Справочника».
- **git не установлен, завис или вернул неожиданный результат**: «ошибка git», сервис продолжает работать.
- **Большой диапазон**: больше N коммитов — «диапазон слишком большой»; сервис не читает больше N + 1 коммита.
- **Нераспознанные коммиты** (`update stuff`, `Merge branch 'x'`, неизвестный тип `wip: …`): пропускаются, попадают в список пропущенных с причиной; на успех операции не влияют. Если нераспознаны все коммиты, результат — секция из одного заголовка и список пропущенных.
- **Коммит с пустым сообщением**: игнорируется полностью, как в CLI (не считается ни прочитанным, ни пропущенным).
- **Breaking-коммит невыбранного типа** и коммит с футером `BREAKING CHANGE:`: всегда в секции Breaking Changes.
- **Повторы и дубликаты типов** (`feat,feat`, два значения `feat`): допустимы, эквивалентны `feat`. **Выбраны все 10 типов**: результат равен результату без фильтра.
- **Пустой список типов** (`""`, `feat,`): ошибка «недопустимые типы», как `changelog-gen --types ""`. «Без фильтра» выражается отсутствием входа «типы».
- **Тип в другом регистре** (`FEAT`): ошибка, регистр учитывается, как в CLI.
- **Ошибки сразу в нескольких входах**: возвращается одна ошибка — первая по порядку проверки (FR-020).
- **История изменилась между запросами** (новый коммит): следующий запрос отражает новую историю, результаты не кэшируются.
- **Параллельные запросы** (страница отправляет не больше одного, но запросы может слать и другой клиент): обрабатываются независимо, друг на друга не влияют.
- **Запрос с чужим адресом назначения** (страница стороннего сайта через DNS rebinding): отклоняется (FR-026).

## Requirements *(mandatory)*

### Functional Requirements

**Операции**

- **FR-001**: Сервис MUST предоставлять операцию «Построить секцию» с двумя необязательными входами: «диапазон» (строка) и «типы» (одно или несколько значений, каждое — список через запятую). Результат — объект «Результат предпросмотра» (см. Key Entities) или «Ошибка».
- **FR-002**: Сервис MUST предоставлять операцию «Справочник» без входов: имя репозитория (имя каталога корня репозитория без пути), допустимые типы в порядке `parser.TYPES`, диапазон по умолчанию (`HEAD`), максимальная длина диапазона (200) и лимит коммитов N. Если каталог сервиса перестал быть git-репозиторием после старта, операция MUST вернуть ошибку «нет репозитория» (`not_a_repository`), а не справочник.
- **FR-003**: Операции MUST быть без состояния: результат зависит только от входа и текущей истории репозитория; результаты MUST NOT кэшироваться ни сервисом, ни клиентом.
- **FR-004**: Сервис MUST только читать историю: никакая операция не создаёт, не изменяет и не удаляет файлы и ссылки git.

**Алгоритм «Построить секцию»**

- **FR-005**: Сервис MUST выполнять шаги строго по порядку: (1) проверить вход (FR-007–FR-011, FR-020) без обращения к git; (2) прочитать сообщения коммитов диапазона в том же порядке, что CLI (новые первыми), игнорируя коммиты с пустым сообщением; (3) разобрать каждое сообщение тем же разборщиком, что CLI (`parser.parse_commit`); (4) отфильтровать: коммит остаётся, если фильтр не задан, или коммит breaking, или его тип входит в выбранные; (5) отрисовать секцию тем же рендером, что CLI (`renderer.render`).
- **FR-006**: Для любого допустимого входа текст секции MUST совпадать с stdout `changelog-gen [RANGE] [--types T]` на той же истории, а причины пропуска — со строками `skip:` CLI (без префикса `skip: `) в том же порядке. Строки в тексте секции разделяются LF независимо от ОС. Совпадение достигается общим кодом с CLI, а не копией (конституция, принцип I).

**Правила для диапазона**

- **FR-007**: Если диапазон не передан, пуст или состоит из пробелов, сервис MUST использовать `HEAD`. Пробельные символы по краям MUST обрезаться. Эффективный диапазон MUST возвращаться в результате.
- **FR-008**: После обрезки диапазон MUST быть отклонён ошибкой «недопустимый диапазон» без обращения к git, если он: (а) длиннее 200 символов; (б) начинается с `-`; (в) содержит пробельный символ (пробел, табуляция, перевод строки); (г) содержит иной управляющий символ (включая нулевой). Остальные символы допустимы: `.`, `~`, `^`, `@`, `{`, `}`, `:`, `/`, `+` и другие входят в синтаксис ревизий git (`v1.0..HEAD`, `HEAD~3`, `main...feature`, `HEAD@{1}`). Ошибка MUST указывать первое нарушенное правило в порядке (а)–(г).
- **FR-009**: Прошедший проверку диапазон MUST передаваться в git так, чтобы git трактовал его только как ревизию — ни как опцию, ни как путь в рабочем дереве. Строка, не разрешимая как ревизия, даёт «диапазон не найден», даже если в рабочем дереве есть файл с таким именем. Это сознательное отличие от CLI.

**Правила для типов**

- **FR-010**: Вход «типы» — список через запятую; пробелы вокруг элементов MUST игнорироваться; несколько значений входа MUST объединяться; дубликаты допустимы; сравнение с учётом регистра. Отсутствие входа означает «без фильтра».
- **FR-011**: Если хотя бы один элемент пуст (`""`, `feat,`) или не входит в допустимые типы, сервис MUST вернуть ошибку «недопустимые типы» без обращения к git. Ошибка MUST содержать все недопустимые значения и полный список допустимых типов. Эффективные типы в результате возвращаются без дубликатов в порядке `parser.TYPES` (или признак «без фильтра»).

**Содержимое результата**

- **FR-012**: Breaking-коммиты (`!` в заголовке или футер `BREAKING CHANGE:`/`BREAKING-CHANGE:`) MUST попадать в секцию Breaking Changes независимо от фильтра типов.
- **FR-013**: Нераспознанные сообщения MUST NOT прерывать операцию и MUST NOT попадать в текст секции. Каждое MUST возвращаться в списке пропущенных: первая строка сообщения и причина (текст ошибки разборщика). Порядок — как в истории.
- **FR-014**: Если после фильтрации не осталось коммитов, операция MUST быть успешной, а текст секции — `## Unreleased` и перевод строки (как в CLI). В репозитории без коммитов при эффективном диапазоне `HEAD` операция MUST быть успешной с таким же текстом и сводкой «прочитано 0»; любой другой диапазон в таком репозитории MUST давать «диапазон не найден». Причину пустого результата клиент определяет по сводке (прочитано 0; все пропущены; все отфильтрованы).
- **FR-015**: Результат MUST содержать сводку: прочитано, включено, отфильтровано, пропущено; всегда прочитано = включено + отфильтровано + пропущено. Текст коммитов в любой кодировке Unicode MUST передаваться без искажений.
- **FR-016**: Если в диапазоне больше N = 1000 коммитов, сервис MUST вернуть ошибку «диапазон слишком большой» со значением N, не возвращая частичный результат, и MUST NOT читать из git больше N + 1 коммита. Усечённая секция не возвращается, чтобы неполный changelog не попал в релиз (решение #12 согласования).
- **FR-017**: Заголовок секции MUST всегда быть `## Unreleased`, как в CLI; входа «версия» нет (решение #10).
- **FR-018**: Результат MUST содержать готовый Markdown, эффективные параметры, сводку и список пропущенных. Структурированный список включённых коммитов и хеши коммитов MUST NOT возвращаться: клиент показывает Markdown буквально (решение #11).

**Ошибки**

- **FR-019**: Каждая ошибка MUST возвращаться данными: машинный код из закрытого перечня, диагностическое сообщение, имя входа-виновника (если есть) и детали. Ошибка MUST NOT содержать трейсбеков, абсолютных путей и сырого вывода git. Перечень кодов:

  | Код | Когда | Детали |
  |-----|-------|--------|
  | `invalid_request` | неизвестный вход, диапазон передан больше одного раза, вход не декодируется | имя входа |
  | `invalid_types` | пустой или неизвестный тип (FR-011) | недопустимые значения, допустимые типы |
  | `invalid_range` | нарушено правило FR-008 | правило: `too_long`, `leading_dash`, `whitespace`, `control_char`; максимальная длина |
  | `unknown_range` | git не разрешил диапазон: нет ревизии, нет upstream, ревизия не коммит, диапазон не `HEAD` в репозитории без коммитов | эффективный диапазон |
  | `range_too_large` | больше N коммитов (FR-016) | лимит N |
  | `not_a_repository` | каталог сервиса перестал быть git-репозиторием (любая операция, включая «Справочник») | — |
  | `git_error` | git не найден, не уложился в 10 секунд или завершился неожиданно | причина: `not_found`, `timeout`, `failed` |
  | `forbidden` | чужой адрес назначения запроса (FR-026) | — |
  | `not_found`, `method_not_allowed` | неизвестный адрес или метод (уровень протокола) | — |

- **FR-020**: Проверки MUST выполняться в порядке: уровень протокола (`forbidden`, `not_found`, `method_not_allowed`) → `invalid_request` → `invalid_types` → `invalid_range` → обращение к git (`not_a_repository` → `unknown_range` → `range_too_large` → `git_error`). Ответ содержит одну ошибку — первую сработавшую.
- **FR-021**: Ни одна ошибка MUST NOT останавливать сервис: следующий корректный запрос обслуживается.

**Запуск и окружение**

- **FR-022**: Сервис запускается командой `changelog-gen-web` и весь срок работы обслуживает git-репозиторий каталога запуска (как CLI, работает и из подкаталога репозитория). Выбрать другой репозиторий через операции MUST NOT быть возможно.
- **FR-023**: Сервис MUST слушать только `127.0.0.1`; адрес не настраивается. Порт задаётся параметром запуска, значение по умолчанию — в контракте (`specs/contracts/changelog-preview-api.md`, п. 1).
- **FR-024**: Если при запуске каталог не является git-репозиторием, порт занят или параметры запуска неверны, сервис MUST завершиться с ненулевым кодом и понятным сообщением в терминале, не открывая порт.
- **FR-025**: Сервис MUST отдавать страницу клиента — один HTML-документ со встроенными стилями и скриптом, без сборки — по корневому адресу, с того же адреса, что и операции; содержимое страницы определяет команда 1.
- **FR-026**: Сервис MUST отклонять запросы, адрес назначения которых не `127.0.0.1:<порт>` или `localhost:<порт>` (защита от DNS rebinding), и MUST NOT разрешать чтение ответов страницам с других источников.

### Key Entities *(include if feature involves data)*

- **Запрос секции**: диапазон (строка, необязательно) и типы (ноль или более значений-списков через запятую). Существует только на время запроса.
- **Эффективные параметры**: диапазон после обрезки и подстановки `HEAD`; множество типов без дубликатов в порядке `parser.TYPES` или признак «без фильтра».
- **Коммит**: тип, scope (необязательно), описание, признак breaking — сущность ядра (`parser.Commit`), сервис её не меняет.
- **Пропущенный коммит**: первая строка сообщения и причина пропуска (текст ошибки разборщика, тот же, что CLI печатает после `skip: `).
- **Сводка**: прочитано, включено, отфильтровано, пропущено (неотрицательные целые; прочитано = сумма остальных).
- **Результат предпросмотра**: эффективные параметры, текст секции (Markdown), сводка, список пропущенных.
- **Справочник**: имя репозитория (имя каталога корня без пути), допустимые типы, диапазон по умолчанию, максимальная длина диапазона, лимит N.
- **Ошибка**: код из перечня FR-019, диагностическое сообщение, вход-виновник (`range`, `types` или нет), детали.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На наборе проверочных историй, включающем все сценарии спеки CLI и сценарии этой спеки, результат сервиса совпадает с выводом CLI в 100% случаев (текст секции и причины пропуска).
- **SC-002**: Разработчик получает секцию для диапазона до 1000 коммитов меньше чем за 2 секунды на обычной рабочей машине, не открывая терминал после запуска сервиса.
- **SC-003**: Ни одно из не менее чем 15 «опасных» значений (начинающихся с `-`, с пробелами и управляющими символами, совпадающих с именами файлов и каталогов, длиннее лимита) не приводит к изменению файлов в каталоге репозитория и не даёт changelog по пути вместо ревизии.
- **SC-004**: 100% ответов-ошибок содержат код из перечня FR-019; 0 ответов содержат трейсбек, абсолютный путь или сырой вывод git.
- **SC-005**: После любой ошибки следующий корректный запрос успешен в 100% случаев.
- **SC-006**: Время ответа на диапазон `HEAD` в репозитории в 100 раз больше лимита не превышает время ответа на диапазон из N коммитов более чем вдвое.

## Assumptions

- Один пользователь, локальная машина, без авторизации (бриф). Клиент отправляет не больше одного запроса одновременно (контракт, п. 2), но сервис не полагается на это: запросы независимы.
- git установлен, доступен в `PATH` и поддерживает явное отделение опций и путей от ревизий (git 2.24+; проверено на 2.51). Сообщения коммитов хранятся в UTF-8.
- `parser` и `renderer` не меняются; чтение истории и фильтр становятся общим кодом CLI и сервиса (конституция, принцип I). Сервис строится на стандартной библиотеке (принцип III).
- Хеши коммитов не возвращаются: CLI их не читает, а список пропущенных идентифицируется первой строкой сообщения.
- Таймаут git — 10 секунд; лимит N = 1000 (согласовано, решение #12).
- Сознательные отличия от CLI (в CLI не переносятся в рамках этой фичи): обрезка пробелов в диапазоне; запрет диапазонов, начинающихся с `-`; диапазон только как ревизия, не путь; ошибки git — кодом, а не трейсбеком (CLI на неверном диапазоне сейчас падает с `CalledProcessError`).
- Вне рамок: запись в `CHANGELOG.md`, подсказки по тегам и веткам (решение #9), заголовок версии (#10), структурированный список коммитов (#11), выбор репозитория, оформление Markdown в HTML на сервере, автоматическое открытие браузера, CORS для других источников.
