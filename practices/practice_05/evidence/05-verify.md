## Проверяющий

```text
Прочитай требования filter-commit-types и изменения.
Найди и запусти команду проверки этого проекта.
Проверь основной, ошибочный и старый сценарии.

```

Проверяющий сверил sha1 89 файлов проекта до и после проверки: ничего не изменилось. Временные репозитории он создавал в `%TEMP%` и удалил их.

## Результат (кратко)

- `bash scripts/check.sh` → `check ok`; ruff: `All checks passed!`; pytest: `41 passed`; `openspec validate --strict` → valid.
- Новый `test_cli.py` прогнан на **старом** пакете: проходят 2 теста (в том числе характеризационный), 18 падают. Значит, эталон верный, а новые тесты проверяют именно новое поведение.
- Старая версия запускалась из `git show practice_04:…/cli.py`. Без `--types` её вывод совпадает с новой версией байт в байт (`cmp` stdout и stderr): 5 временных историй и история курса (`practice_04~12..`, `~30..`, весь `HEAD`; 6/39/96 строк `skip:`).
- По сценариям:
  - **основной** (`feat,fix`; пробелы; повтор; флаг до и после диапазона; история курса) — соответствует;
  - **граница** (breaking неотобранного типа, breaking через футер, пустой результат) — соответствует;
  - **ошибочный** (`feature`, `""`, `feat,`, `,`, `FEAT`, вне git, без git в PATH, `--foo`, `--no-merges`, `--since=…`, `--type`, два позиционных) — код 2, stdout пуст, нет Traceback;
  - **старый** — совпадает. Задекларированный BREAKING: `--no-merges` раньше давал 0, теперь 2.
- **Расхождений с требованиями нет.**

## Замечания проверяющего, не нарушающие требований

| # | Замечание | Решение |
|---|---|---|
| 1 | Консольный скрипт на Windows печатает `\r\n`: текстовый режим stdout. Старая версия ведёт себя так же | Свойство платформы, не регрессия. Не меняем |
| 2 | `changelog-gen -- --output=injected.txt` пишет файл через `git log` | Риск описан в design и сознательно не взят в изменение. Перенесён в ДЗ (сервис принимает ввод по сети) |
| 3 | Для пустого значения сообщение `unknown type ''` | Требование выполняется; косметика, не меняем |
| 4 | Неверный диапазон по-прежнему падает с трейсбеком | Вне границ (указано в proposal); кандидат на следующее изменение |
| 5 | Изменены только `cli.py` и `test_cli.py` | Соответствует proposal |

## Решение человека (делегировано)

**Фича принята.** Почему: все 5 условий приёмки из explore подтверждены не автором, а независимыми запусками с доказательствами. Старое поведение совпадает байт в байт. Единственное ломающее изменение (`--no-merges` и прочие pass-through флаги git) задекларировано в proposal как BREAKING. Переходим к шагу 6.
