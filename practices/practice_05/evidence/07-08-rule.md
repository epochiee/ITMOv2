# Часть 2. Шаги 7–8: правило OpenSpec для проекта

## Шаг 7. Связанная фича и правило

```text
/opsx:propose write-changelog-file
Цель: флаг --output FILE — дописать сгенерированную секцию в начало CHANGELOG.md
вместо печати в stdout (связанная фича к --types). Остановись до apply.
```

Change `write-changelog-file`: proposal, delta-spec для **существующей** capability `changelog-cli` (2 MODIFIED + 3 ADDED — первый MODIFIED в проекте), design, tasks. `openspec validate --strict` — OK. До apply не шли, код не менялся.

Фрагмент «до» — раздел `## Взаимодействие` из design.md, созданного **без** правила (`openspec instructions design` тогда возвращал `rules: None`):

- [`07-fragment-before.md`](07-fragment-before.md) — только фрагмент;
- [`07-design-before.md`](07-design-before.md) — весь design.md до правки.

Правило дописано в текущий `openspec/config.yaml` одним блоком `rules` (до этого `rules` был только в закомментированном примере, второй ключ не создавали; `grep -c '^rules:'` → 1). Diff: [`07-config.diff`](07-config.diff).

```yaml
rules:
  design:
    - Объясни взаимодействие диаграммой Mermaid.
```

## Шаг 8. Применение к тому же фрагменту

```text
/opsx:update write-changelog-file
Перед правкой выполни в shell:
openspec instructions design --change write-changelog-file --json
Проверь в ответе моё актуальное правило.
Примени его к тому же фрагменту; покажи diff.
Сохрани смысл и границы; правь после подтверждения.
Код не меняй.
```

1. Свежие инструкции: [`08-instructions.txt`](08-instructions.txt) — в `rules` для `design` есть «Объясни взаимодействие диаграммой Mermaid.»; для `specs` — `None` (правило адресное, на specs не влияет).
2. Предложенная правка: в начало раздела «Взаимодействие» добавлена `sequenceDiagram` (пользователь → `cli.main` → `git log` → parser/фильтр → renderer → файловая система, две ветки `alt`: «коммитов нет» и «OSError / успех»). Проза оставлена как есть.
3. Diff фрагмента: [`08-fragment.diff`](08-fragment.diff) — **+30 строк, 0 удалённых**; по всему design.md тоже только `30 insertions(+)`. Остальные артефакты и код не менялись; `openspec validate --strict` — OK.
4. Подтверждение (делегировано): diff принят. Смысл сохранён — каждое действие диаграммы есть в прозе (пустой результат до открытия файла, временный файл, `os.replace`, удаление временного файла при `OSError`, коды 0/1, сообщения), новых шагов и обещаний диаграмма не добавляет. Границы (`Non-Goals`, `Risks`) не тронуты.
5. До/после сравнены, Mermaid открыт как диаграмма: [`08-mermaid-preview.html`](08-mermaid-preview.html) (рендер через mermaid@11.4.1 с jsDelivr) — все 6 участников и обе ветки `alt` отрисованы. На GitHub блок ```` ```mermaid ```` в design.md рендерится и без этой страницы.

Правило остаётся в `config.yaml` и будет попадать в инструкции каждого следующего design этого проекта. Design создаётся не всегда (он условный в схеме spec-driven), поэтому на изменения без design правило не действует.
