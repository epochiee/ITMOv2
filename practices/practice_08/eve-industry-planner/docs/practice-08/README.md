# Практика 8 · «Верфь»

Игрок EVE Online выбирает чертёж, задаёт размер партии, цены материалов, цену продажи и сборы. Калькулятор показывает объём производства ещё при заполнении формы. После отправки игрок видит затраты, выручку, итог и минимальную цену продажи для выхода в ноль.

## Запуск и контрольный заказ

Из каталога `practices/practice_08/eve-industry-planner` в ITMOv2, с Node.js 22.13 или новее:

```sh
npm ci
npm run dev
```

Откройте браузер по адресу `http://127.0.0.1:5173`. Каталог и расчёт обслуживает тот же локальный Express. Настройки и примеры запросов есть в [README проекта](../../README.md).

1. Нажмите `Tab` и выберите стрелкой «Чертёж щитового модуля». Введите **10** запусков. Форма покажет выпуск 10 модулей, 200 единиц тританиума и 100 единиц пайерита.
2. Введите **1000** и **1200** в поля цены тританиума и пайерита. Укажите цену продажи **45000**, сбор за работу **20000** и сбор при продаже **10000**.
3. Перейдите через `Tab` на «Рассчитать» и нажмите `Enter`. В сводке появятся прибыль **100 000 ISK**, полные затраты **350 000 ISK** и цена безубыточности **35 000 ISK** за модуль. Фокус перейдёт на заголовок результата.
4. Измените число запусков. Сводка покажет, что предыдущий результат устарел, и предложит пересчёт.

Для браузерных тестов в Windows используется установленный Edge. Чтобы выбрать Chrome, задайте `BROWSER_CHANNEL=chrome`. В Linux и macOS установите Chromium через `npx playwright install chromium`. При отсутствии Make выполните последовательно `npm test`, `npm run build`, `npm run test:integration`.

## Макет и приложение

Откройте [автономный HTML-прототип](prototype.html) в браузере. В верхнем списке доступны девять состояний, включая ввод, загрузку каталога и расчёта, пустые данные, валидацию, ошибку каталога и расчёта, успех. При выборе чертежа прототип подставляет данные контрольного заказа, а кнопка показывает задержку и сводку этого заказа.

В макете и приложении форма и сводка стоят рядом на широком экране и друг под другом на узком. Основа каждой карточки, группировка полей, расположение подсказок и выделение прибыли совпадают. В приложении карточки реализованы через `Paper`, поля через `TextField`, действия через `Button`, ошибки через `Alert` и загрузка расчёта через `CircularProgress`. Цвета, шрифты, скругления и шаг отступов берутся из темы. ## Как подменяются ответы

В [тестах формы](../../tests/form.test.tsx) Vitest подставляет `fetch` через `vi.stubGlobal`. Ответы имеют формат Express. Успех возвращает `result`, пустой каталог содержит `{ "blueprints": [] }`, ошибки возвращают `error` с `code`, `message` и полями для HTTP 422. Незавершённый Promise удерживает запрос в ожидании, пока тест проверяет блокировку.

В [браузерных тестах состояний](../../integration/states.spec.ts) Playwright перехватывает GET или POST через `page.route` и отдаёт подготовленный JSON через `route.fulfill`. В [контрольном браузерном заказе](../../integration/order.spec.ts) POST идёт в Express. Тест сравнивает весь исходящий запрос и ответ с тем же [JSON-примером](api-example.json), а затем проверяет сводку в интерфейсе.

Кнопка и поля становятся недоступны на время запроса. Обработчик `submit` дополнительно ставит синхронную блокировку через `useRef` до первого `await` и снимает её в `finally`. Для проверки чувствительности теста блокировку временно убрали. Тест зафиксировал три POST вместо одного. После восстановления тест прошёл.

## Вклад AI и правки после проверки

Codex подготовил HTML-прототип на основе существующего интерфейса, доработал форму и тему Material UI, расширил клиентские тесты и добавил браузерный сценарий с клавиатуры. Express и формулы расчёта использованы из проекта.

Примеры формулировок для Codex:

- «Спроектируй автономный HTML-прототип заказа щитовых модулей. Покажи форму и сводку на широком и узком экране, добавь переключение загрузки, пустого каталога, ошибки и результата».
- «Доработай существующую форму на Material UI. Переиспользуй TextField, Paper, Button и Alert. Проверь фокус после ошибки и расчёта, сохрани значения при сбое POST».
- «Проверь в тестах видимые действия и итоги. Подмени реальные форматы GET и POST, удержи ответ для двух попыток отправки и пройди отдельно весь сценарий через настоящий Express».

После проверки доступности уточнили имена материальных полей и передачу фокуса. В тесте ожидания пустого каталога исправили гонку, при которой поиск по роли мог найти ещё видимый статус загрузки. JSON-экспорт подключили с атрибутом импорта, чтобы одни и те же данные читали Vitest и Playwright. Полный заказ проверили против настоящего API, а защиту от повторной отправки проверили временным снятием блокировки.
