# «Верфь» — техническое задание на самостоятельный MVP

## 1. Задача

Сделать веб-калькулятор производственных заказов для игроков EVE Online. Перед запуском партии игрок хочет понять, сколько материалов и ISK потребуется, по какой цене изделие окупится и сколько можно заработать. Он выбирает чертёж, вводит число запусков и цены, затем получает расчёт.

Результат — **самостоятельное приложение в отдельном репозитории** с русскоязычным интерфейсом, локальным API и автоматическими проверками. Для работы достаточно установить зависимости. n8n, GitHub-бот, Gmail, учебные workflow, макет и материалы для защиты относятся к отдельным практическим работам. Контракт HTTP API позволит подключить их позднее.

MVP включает один экран, три демонстрационных чертежа, ручной ввод цен и расчёт одной партии. Каталог хранится в репозитории. База данных и аккаунты не нужны. История, рыночные котировки, ESI, импорт игровых данных, эффективность чертежей, бонусы сооружений, производственные индексы, ставки игровых налогов и многоступенчатое производство за пределами MVP. На экране обозначить условный характер рецептов и ручной ввод цен.

## 2. Основной сценарий

1. Игрок выбирает чертёж. Видит норму расхода материалов и выпуск за один запуск.
2. Вводит число запусков. Форма показывает объёмы материалов и выпуск на всю партию.
3. Вводит цену единицы каждого материала, сбор за работу, цену продажи единицы изделия и сбор при продаже. Оба сбора задаются как фиксированные суммы **за всю партию**, по умолчанию равные нулю.
4. Нажимает «Рассчитать». Сервер проверяет данные и вычисляет результат. Интерфейс показывает затраты, выручку, прибыль или убыток и цену безубыточности.
5. Меняет параметры и рассчитывает повторно. После правки полей ранее полученный результат помечается как устаревший до нового успешного расчёта.

При смене чертежа сохранить цены материалов с совпадающим ID, число запусков и общие сборы. Новые цены материалов оставить пустыми. Цену продажи очистить, поскольку меняется изделие. Пустая цена означает отсутствие ввода. Явно введённый ноль допустим.

## 3. Каталог

Поставить статический JSON со стабильными ID. Все количества — положительные целые. ID чертежей уникальны, каждый материал представлен в чертеже один раз. Названия и нормы ниже — условные данные стенда.

| ID чертежа | Изделие | Изделий за запуск | Материалы на запуск |
|---|---|---:|---|
| `shield-module` | Щитовой модуль | 1 | Тританиум (`tritanium`) × 20, пайерит (`pyerite`) × 10 |
| `repair-module` | Ремонтный модуль | 1 | Тританиум (`tritanium`) × 15, мексаллон (`mexallon`) × 5 |
| `training-ammo` | Учебный боеприпас | 100 | Тританиум (`tritanium`) × 8, пайерит (`pyerite`) × 3 |

## 4. Расчёт

Входные деньги измеряются в целых ISK. Сервер считает точные суммы, например через `bigint`. В JSON денежные результаты передаются строками. Количество изделий, материалов и запусков передаётся целыми JSON-числами.

| Показатель | Формула |
|---|---|
| Изделий в партии | Выход изделий за запуск × число запусков |
| Количество материала | Норма на запуск × число запусков |
| Стоимость материала | Количество материала × цена единицы |
| Стоимость материалов | Сумма стоимостей отдельных материалов |
| Производственная себестоимость | Стоимость материалов + сбор за работу |
| Полные затраты | Производственная себестоимость + сбор при продаже |
| Удельная себестоимость с учётом продажи | Полные затраты ÷ количество изделий |
| Выручка | Цена продажи единицы × количество изделий |
| Прибыль | Выручка − полные затраты |
| Цена безубыточности | Полные затраты ÷ количество изделий, с округлением вверх до целого ISK |

Удельная себестоимость возвращается с двумя знаками после точки, половины округляются вверх. Выручка и прибыль считаются по точным суммам партии. Результат классифицируется как `profit`, `loss` или `break_even` по знаку прибыли. Нормы и выход изделий берутся из серверного каталога.

**Контрольный пример.** Щитовой модуль, 10 запусков, цены тританиума и пайерита по 1 000 и 1 200 ISK, сбор за работу 20 000 ISK, сбор при продаже 10 000 ISK, цена изделия 45 000 ISK. Выпуск — 10 изделий. Нужно 200 единиц тританиума и 100 пайерита. Материалы стоят 320 000 ISK, производственная себестоимость составляет 340 000 ISK, полные затраты — 350 000 ISK, выручка — 450 000 ISK, прибыль — 100 000 ISK, цена безубыточности — 35 000 ISK.

## 5. HTTP API

JSON, префикс `/api/v1`. Фронтенд использует относительные URL. Локально Vite может проксировать API на сервер. Сервер итоговой сборки может раздавать клиентские файлы с того же origin.

### GET /api/v1/blueprints

Ответ `200 OK`:

~~~json
{
  "blueprints": [
    {
      "id": "shield-module",
      "name": "Чертёж щитового модуля",
      "productName": "Щитовой модуль",
      "outputPerRun": 1,
      "materials": [
        { "id": "tritanium", "name": "Тританиум", "quantityPerRun": 20 },
        { "id": "pyerite", "name": "Пайерит", "quantityPerRun": 10 }
      ]
    }
  ]
}
~~~

В примере показана одна запись. Рабочий каталог содержит три чертежа. Пустой каталог представляется пустым массивом.

### POST /api/v1/calculations

Тело запроса с `Content-Type: application/json`:

~~~json
{
  "blueprintId": "shield-module",
  "runs": 10,
  "materialUnitPricesIsk": { "tritanium": "1000", "pyerite": "1200" },
  "jobFeeIsk": "20000",
  "saleFeeIsk": "10000",
  "saleUnitPriceIsk": "45000"
}
~~~

Ответ `200 OK`:

~~~json
{
  "blueprintId": "shield-module",
  "productName": "Щитовой модуль",
  "runs": 10,
  "productQuantity": 10,
  "materials": [
    { "id": "tritanium", "name": "Тританиум", "quantity": 200, "unitPriceIsk": "1000", "totalCostIsk": "200000" },
    { "id": "pyerite", "name": "Пайерит", "quantity": 100, "unitPriceIsk": "1200", "totalCostIsk": "120000" }
  ],
  "totals": {
    "materialsCostIsk": "320000",
    "jobFeeIsk": "20000",
    "saleFeeIsk": "10000",
    "productionCostIsk": "340000",
    "totalCostIsk": "350000",
    "unitCostIsk": "35000.00",
    "revenueIsk": "450000",
    "profitIsk": "100000",
    "breakEvenUnitPriceIsk": "35000",
    "outcome": "profit"
  }
}
~~~

### Валидация и ошибки

- Все поля запроса обязательны. `blueprintId` соответствует известному чертежу.
- `runs` — JSON-число, целое от 1 до 10 000 включительно.
- Денежный вход — каноническая строка целого числа от 0 до 1 000 000 000 000 включительно. В API запретить дроби, знак, пробелы, экспоненциальную запись и ведущие нули у ненулевых значений. Интерфейс убирает случайные пробелы по краям поля.
- Карта цен содержит ровно ID материалов выбранного чертежа. Пропущенные и неизвестные ID отклоняются.
- Некорректный JSON даёт `400 INVALID_JSON`, ошибки параметров — `422 VALIDATION_ERROR`, неожиданная серверная ошибка — `500 INTERNAL_ERROR` с общим сообщением.
- Формат ошибки: `{ "error": { "code": "...", "message": "...", "fields": { "runs": "Укажи целое число от 1 до 10 000" } } }`. `fields` передаётся для ошибок полей. Ключ цены материала имеет вид `materialUnitPricesIsk.tritanium`.

## 6. Интерфейс

На одной странице разместить форму и результат. В форме указать, относится ли денежная сумма к единице материала, единице изделия или всей партии. По умолчанию установлен один запуск и чертёж не выбран. В результате показать детализацию материалов, производственную и полную себестоимость, удельную себестоимость с учётом продажи, выручку, исход с суммой и цену безубыточности. Форматировать ISK с разделителями разрядов без потери точности. Прибыль, убыток и выход в ноль обозначить текстом.

| Состояние | Поведение |
|---|---|
| Каталог загружается | Индикатор загрузки, форма временно недоступна |
| Каталог пуст | Сообщение «Нет доступных чертежей» |
| Ошибка каталога | Сообщение и повторная загрузка |
| Расчёт ещё не выполнен | Подсказка в области результата |
| Форма некорректна | Сообщения рядом с полями, сетевой запрос не отправляется |
| Расчёт выполняется | Индикатор и блокировка полей и кнопки. Двойной клик или Enter не создаёт второй запрос |
| Расчёт выполнен | Результат со всеми суммами |
| Ошибка расчёта | Понятное сообщение, ввод сохранён, доступен повторный запуск |

Подписи и ошибки связать с полями. Поддержать клавиатуру и видимый фокус. На узком экране форма и результат размещаются вертикально, данные материалов остаются читаемыми. Использовать компоненты и общую тему Material UI. Оформление самостоятельное, без игровых логотипов и изображений.

## 7. Техническое устройство

Предлагаемый стек — TypeScript, React, Material UI, Vite, Node.js и Express. Для проверок подойдут Vitest и React Testing Library. Конкретные версии выбрать в рабочем окружении и закрепить lock-файлом.

Выделить статический каталог, серверную валидацию, чистую доменную функцию и HTTP-обработчики. Клиент отвечает за форму и предварительный показ количеств. Денежные итоги рассчитывает сервер. Типы контракта можно вынести в общий модуль. Приложение запускается локально без секретов и внешних API.

## 8. Критерии приёмки

| Уровень | Что проверить |
|---|---|
| Домен | Контрольный пример, положительная, нулевая и отрицательная прибыль, выход нескольких изделий за запуск, округление, большие денежные итоги без потери точности |
| API | Каталог, успешный запрос, неизвестный чертёж, лишняя или отсутствующая цена, недопустимая цена, дробное число запусков, некорректный JSON |
| Интерфейс | Загрузка, пустой каталог, ошибки полей, ожидание, отсутствие повторного запроса, результат, сохранение ввода после ошибки и возможность повторить |
| Клиентский сценарий | Выбор чертежа → заполнение формы → расчёт → итоговые суммы на экране. Тестовые ответы API соответствуют контракту |
| Реальная интеграция | Пройти контрольный пример через запущенный клиент и API, сверить суммы |

Для проверки округления взять `training-ammo`, один запуск, нулевые цены материалов, сбор за работу 101 ISK и сбор при продаже 0 ISK. Тогда 100 изделий стоят 101 ISK, удельная себестоимость равна 1,01 ISK, а целая цена безубыточности — 2 ISK.
